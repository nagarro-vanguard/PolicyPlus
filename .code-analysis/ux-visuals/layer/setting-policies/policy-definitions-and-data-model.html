Policy definitions and data model

Reads policy definition and comment files, resolves their references and holds the result in memory for the screens. In Setting policies: 0 actions and 9 business rules. Part of its code is also used by other capabilities.

Business rules in this layer (9)

A policy comment file (CMTX) is refused as a whole when it repeats a namespace prefix, a policy reference or a string id. A comment file that cannot be loaded is treated as 'comments unavailable' for that policy source.
PolicyPlus/CmtxFile.vb:13 · Screens: Main
When policy comments are saved, each comment is stored as its own text under a unique id, and its policy is referenced through a short prefix standing for the policy's namespace. Each distinct namespace gets one prefix; the text of every comment gets a new running number so ids never collide. A policy id with no colon cannot be saved.
PolicyPlus/CmtxFile.vb:47 · Screens: Main
When the comment file is read back into comments, each policy is identified by its prefix's namespace and its comment id; the comment text is the string the comment points to. A comment pointing to a prefix or string that is not in the file makes the whole file unreadable.
PolicyPlus/CmtxFile.vb:66 · Screens: Main
A saved comment file always states revision 1.0, schema version 1.0 and minimum required revision 1.0, whatever its source declared, and holds every prefix, comment and string currently held.
PolicyPlus/CmtxFile.vb:81 · Screens: Main
A displayed name or explanation resolves as follows: empty text stays empty; text not written as $(string.<id>) is shown as it is; $(string.<id>) is replaced by that text from the localized-text file; an id missing from the file leaves the $(string.<id>) text visible.
PolicyPlus/AdmxBundle.vb:193 · Screens: EditSetting
A support definition is combined as All-of only when the caller opts in to honouring All-of and the definition is marked All-of; otherwise every definition is treated as any-one-of. An All-of definition is met when every entry is met, so one with no entries is met. An any-one-of definition is met when any entry is met, so one with no entries is not met. Products are checked before nested definitions.
PolicyPlus/PolicyProcessing.vb:380 · Screens: Main
A policy with no 'supported on' definition, or a blank one, counts as supported only when the caller allows unknown ('literal') support text. Entries naming no known product follow the same allowance.
PolicyPlus/PolicyProcessing.vb:382 · Screens: Main
A plain supported-on product entry is met when the computer lists that product, or, for a parent product, when it lists any sub-product (or a sub-product's child). A version-range entry is met only by a sub-product, or its child, whose version lies within the range, minimum 0 and maximum the highest known version by default; listing the parent itself does not meet it. A product with no sub-products is met only by being listed. An entry with no known product is met only when unknown entries are approved.
PolicyPlus/PolicyProcessing.vb:383 · Screens: Main
A support definition already visited earlier in the same check counts as not met, even if it was met then and is not part of a circular reference. For an All-of definition, a shared sub-definition reached from two places therefore fails the whole definition the second time.
