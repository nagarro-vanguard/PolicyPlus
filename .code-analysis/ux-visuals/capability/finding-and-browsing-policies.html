Assumptions we made (2)

The right-click menu on a category or policy mostly serves browsing (opening a category, showing details), but also reaches the setting editor, element inspector and SPOL fragment viewer, which belong to setting policies and definitions.
Why: One handler dispatches every menu action, so no single capability owns it; we assign it to browsing because most actions show or open the selected item. If we are wrong: If the editor and inspector actions matter more, this entry point would move to setting policies and browsing would lose its right-click route.
What the person sees when Find by Registry is given an invalid pattern is assumed: the results dialog likely keeps showing the searching status, with Stop still enabled, and no hits or finishing message.
Why: The error is raised on a background task with no handler; its visible effect depends on the Windows Forms runtime, which is not shown. If we are wrong: A rebuild might show an error or finish the search instead of leaving the dialog apparently still searching.
