Assumptions we made (2)

Whether a policy save asks Windows to refresh or the program applies the change itself depends on a fixed list of Windows edition codes. Whether newer editions are on that list is assumed.
Why: The list is a fixed set of numbers; which Windows editions they stand for is outside the code. If we are wrong: On an unlisted edition with Group Policy, saves would apply changes to the registry directly instead of refreshing policy.
Which Windows edition the computer is, and so whether Group Policy tools are offered, comes from a Windows system call. The code holds only a list of accepted edition codes, so new editions are missed until it is updated.
Why: The edition code is returned by the operating system; the list's coverage of current Windows editions is not checkable from the code. If we are wrong: A supported edition is wrongly reported as lacking Group Policy, or an unsupported one passes.
