Assumptions we made (4)

When several sibling language folders share the chosen language, such as de-AT and de-CH for de-DE, the one used depends on the order Windows lists folders. The code states no preference among them.
Why: The choice rests on the operating system's folder listing order, which no file in the code fixes. If we are wrong: People may see definitions in a different regional variant of their language than expected.
When linking stops the load with an error, what the person sees depends on the calling screen, which reports a failed load but whose exact message and the state left in the workspace we did not trace.
Why: The linking code raises unhandled errors; their handling lies in the calling screens, outside these blocks. If we are wrong: A person might see a different message, or be left with a partly loaded set of definitions.
The download assumes Microsoft still serves the fixed Windows 11 26H2 package at its link, with definitions at the expected folder inside it. If not, the download fails with a step message.
Why: The package link and its internal folder layout are on Microsoft's server, outside the code. If we are wrong: Downloads fail at the download or move step, and the person cannot fetch definitions from within the program.
Offering the domain definitions folder relies on Windows reporting the computer's domain. When Windows cannot, the choice is silently disabled, so domain-joined machines without reachable controllers cannot pick it.
Why: The domain lookup is a framework call with no source here. If we are wrong: The domain choice could appear or stay disabled differently than described.
