# Offer the missing policy definitions once on first use

## Story

As a person using the product, I want on the first use of the program, record that the welcome offer has been considered, work out whether this Windows edition lacks the full set of policy definitions, and if so show a single welcome question offering to download them; Yes starts the download., so that people on editions without Group Policy support get the full set of policy definitions offered without having to notice they are missing, and the offer is considered only once..

## Context

This ports behaviour of the existing product, described in the attachment: 5 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Install Microsoft's policy definitions in one go.

Open points, to settle before it is built:
- No rule says what happens when the person answers No beyond not downloading; should the program do or say anything more?
- The journey asks for a standing invitation to get the definitions later, but no rule or decision states it and today the welcome text only mentions Help | Acquire ADMX Files; should a standing invitation be built, and if so what and where?
- The earlier remembered choice lived in the Windows registry and is not carried to the new store; should people who already saw the offer be asked again once?

## Acceptance criteria

**AC-1: The program records that it has been considered, even.**
Given the program is shown for the first time, when the welcome offer is considered, then the program records that it has been considered, even when no offer is made, and never considers it again on later starts.

**AC-2: That category counts as orphaned.**
Given a category whose definition names a parent that is not among the loaded definitions, when the program checks for missing definitions, then that category counts as orphaned.

**AC-3: It counts as empty.**
Given a category that holds no subcategories and no policies, even hidden ones, when the program checks for missing definitions, then it counts as empty.

**AC-4: The computer counts as having Group Policy support; given.**
Given the Windows edition reported by the computer is one of the 59 fixed edition codes, then the computer counts as having Group Policy support; given the edition cannot be read, then it counts as having none.

**AC-5: The person sees "Welcome to Policy Plus! Home editions.**
Given the offer is being considered, the edition has no Group Policy support and more than two non-empty categories name a missing parent, when the main window is shown, then the person sees "Welcome to Policy Plus! Home editions do not come with the full set of policy definitions. Would you like to download them now? This can also be done later with Help | Acquire ADMX Files."; otherwise no offer is made.

**AC-6: The download dialog opens.**
Given the welcome question is shown, when the person answers Yes, then the download dialog opens.

## Terminologies

- Orphaned category: A category with no parent among the loaded definitions although its definition names one; not a category that simply sits at the top.
- Empty category: A category holding no subcategories and no policies at all, hidden ones counted; not a category whose policies are all hidden.
- Group Policy support: Whether the computer's Windows edition is one of the fixed list of 59 editions that have the Group Policy infrastructure; not whether definitions are loaded.
- Welcome offer: The one question shown on first use offering to download the policy definitions; not the Acquire ADMX Files command in the Help menu.
- Offer considered: The remembered fact that the welcome offer has been weighed on a first use, whether or not it was shown; not the person's answer to it.
