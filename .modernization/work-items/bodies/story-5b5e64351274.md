# Change the data of a value in a policy file in either number form

## Story

As a person using the product, I want a person picks an existing value in a policy file and types its new data. A number is shown and accepted in decimal or hexadecimal as typed, with both forms shown, so there is no mode to switch. Text and lists of text are entered as such., so that administrators editing a policy file directly can correct a value's data without first knowing or switching which number form is on..

## Context

This ports behaviour of the existing product, described in the attachment: 0 rules it must keep and the reading of the code behind them.

Open points, to settle before it is built:
- How does a person mark a typed number as hexadecimal, and how is a number typed without that mark read?
- How are the decimal and hexadecimal forms of a number's current data shown together when a value is opened for editing?
- What does a person see when they back out of entering new data, and which kinds of value (number, text, list of texts) are entered how?

## Acceptance criteria

**AC-1: The value is set to the largest allowed value.**
Given a typed hexadecimal number that is too large to fit, when the person confirms, then the value is set to the largest allowed value.

**AC-2: The value is left unchanged.**
Given typed text that is not a hexadecimal number, when the person confirms, then the value is left unchanged.

**AC-3: The value's data is replaced by the confirmed data.**
Given new data is confirmed for a value, when the change is kept, then the value's data is replaced by the confirmed data and its name and kind stay the same.

**AC-4: The value stays selected.**
Given new data is confirmed for a value, when the change is kept, then the value stays selected.

## Terminologies

- Value data: The content stored in a named value of a policy file, such as a number, a text or a list of texts; it is not the value's name or its kind.
