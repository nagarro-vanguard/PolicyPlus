# Refuse unusable registry terms and start the search when asked

## Story

As a person using the product, I want when the person asks to search by registry key and value, the system refuses empty terms and a key that begins with a root key, telling them why, and otherwise starts a search with exactly what they entered., so that people hear at once, with a clear message, why their terms cannot be searched, and usable terms are never altered..

## Context

This ports behaviour of the existing product, described in the attachment: 3 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Watch search hits arrive and stop the search when enough is found.

Open points, to settle before it is built:
- Should the system split one pasted line into a key and a value, and show that reading so the person can correct it? No rule or decision states this.
- Should the check for empty terms and a root key run while the person types, or only when they ask to search? The rules state it only when they ask.

## Acceptance criteria

**AC-1: No search runs and they are told "Please enter.**
Given the key and the value are both empty, when the person asks to search, then no search runs and they are told "Please enter search terms."

**AC-2: No search runs and they are told "Policies' root.**
Given the key text starts with HKLM\, HKCU\, HKEY_LOCAL_MACHINE\ or HKEY_CURRENT_USER\, when the person asks to search, then no search runs and they are told "Policies' root keys are determined only by their section. Remove the root key from the search terms and try again."

**AC-3: A search starts with exactly what they entered.**
Given the terms are usable, when the person asks to search, then a search starts with exactly what they entered.

## Terminologies

- Registry line: The single line of text a person gives about a setting, such as a full path ending in a value name; it is not yet divided into key and value.
- Registry key: The path part of a setting that a policy reads or writes; it is not the name of the value held under it.
- Registry value name: The name of one setting held under a key; it is not the key path.
