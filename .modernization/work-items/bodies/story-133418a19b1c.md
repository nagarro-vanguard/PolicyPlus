# Prove the journey: Choose the language in which policy definition tex...

## Problem

- the journey keeps working as the product changes, in the interface the team ships

## Goal

- an acceptance test that does the journey from its first step to its last, as people will do it

## Acceptance criteria

- Given the product is ready, when the test does "Say which language the definition text should use", then checks the language is two parts around a hyphen and refuses it with a plain message otherwise; closes without change when it equals the language already stored..
- Given the product is ready, when the test does "Have the language remembered and applied", then saves the language at once and asks whether to reload the workspace now; if yes, clears it and reloads the definitions from the saved folder, otherwise it applies at the next load..

## Scope

- packages/contracts (the Contracts layer)
- packages/domain (the Domain layer)
- packages/database (the Database layer)
- apps/api (the API service layer)
- packages/ui (the UI components layer)
- apps/web (the Web app layer)
- apps/e2e (the End-to-end tests layer)
- packages/tooling (the Tooling layer)

## Out of scope

- Anything a later story builds on top of this.
