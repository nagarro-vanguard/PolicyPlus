# Keep the browser view consistent after view or edit changes

## Problem

- People are never left on a hidden category or a stale list.

## Goal

- Move to the nearest visible category and refresh the list after a view setting or an accepted edit.

## Acceptance criteria

- Given a view setting changes, when applied, then the view moves up to the nearest visible category, drops the selected policy if moved or hidden, rebuilds tree and list, and a kept policy shows in the information pane only, not highlighted.
- Given an edit dialog is accepted, when it closes, then the list refreshes in place if the category is visible, otherwise moves to the nearest visible one, and nothing is written to disk until Save.

## Scope

- packages/tooling (the Tooling layer)
- packages/domain (the Domain layer)
- packages/contracts (the Contracts layer)
- packages/data (the Data layer)
- apps/api (the Services layer)
- packages/ui (the Components layer)
- apps/web (the Screens layer)
- apps/e2e (the Black-box tests layer)

## Out of scope

- Anything a later story builds on top of this.
