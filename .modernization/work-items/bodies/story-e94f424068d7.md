# Decide whether a policy is enabled, disabled or unsupported

## Problem

- People rely on the state shown for a policy; it must match what the legacy product reports.

## Goal

- Domain rules that weigh the stored values of a policy to give its state, tell preferences from managed policies and check support against chosen products.

## Acceptance criteria

- Given enabled and disabled evidence, when the state is decided, then it is Enabled if enabled exceeds disabled, Disabled if the reverse, Not configured with none, and Unclear when both are equal and above zero.
- Given a checkbox element, when evidence is counted, then a value marked for deletion counts one deleted element; otherwise each present off value or off-list value counts a tenth of a deleted element and each present on value or on-list value counts one present element; a checkbox whose template declares no on value or on list adds no present evidence, even if it holds 1.
- Given a stored value, when it is checked as present, then a deletion marker must be marked for deletion, a number must be a whole number equal to the expected one, text must equal the expected text, and a value of the wrong kind is not present.
- Given a policy naming a registry key outside software\policies, software\microsoft\windows\currentversion\policies and system\currentcontrolset\policies, when it is classified, then it is a preference, otherwise a managed policy.
- Given a policy listing no supported-on information or an entry naming no known product, when support is checked, then it counts as supported only if unlisted policies are allowed.
- Given a support entry for a product, when it is checked, then it is met if it is not a version range and that exact product is chosen, or if any version or sub-product beneath the product is chosen.

## Scope

- packages/tooling (the Tooling layer)
- packages/domain (the Domain layer)
- packages/contracts (the Contracts layer)
- packages/data (the Data layer)
- apps/api (the Services layer)
- packages/ui (the Components layer)
- apps/web (the Screens layer)
- apps/e2e (the Black-box tests layer)

## Out of scope

- Anything a later story builds on top of this.
