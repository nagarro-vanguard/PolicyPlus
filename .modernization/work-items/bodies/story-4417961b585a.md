# Set up the test tooling for every layer

## Problem

- A story can be called done only when its layer checks and its black-box test pass, and the tests catch what can really break: migrations, SQL behaviour and what a user sees.

## Goal

- Vitest in each code layer, a real PostgreSQL test database for the Data layer, the HttpApi test client for the Services layer, Storybook stories for the components, Vitest tests of pure logic in the Screens layer, and Playwright with axe in the black-box layer.

## Acceptance criteria

- Given a layer with a Vitest test, when `bun run test` runs, then Turborepo runs that layer's tests and reports a failing test as a failed task.
- Given a table of sample ADMX, ADML, POL, REG, CMTX and SPOL files and a round-trip test for a parser and its writer, when the Domain tests run, then each sample is checked by an example-based test and the round-trip test passes.
- Given the local database is running, when the Data tests run, then they connect to a real PostgreSQL test database, apply the migrations and use no in-memory fake.
- Given a handler of the contract, when a Services test calls it through the HttpApi test client, then the test receives the handler's response without starting a network server.
- Given a component, when Storybook is built, then the component's story renders and a component without a story is reported.
- Given a pure function in the Screens layer, when the Screens tests run, then a Vitest test of that function runs and passes.
- Given the running product and a seeded database, when Playwright runs a screen test, then axe checks that screen and any violation fails the test.
- Given the project's CI, when it runs the Data tests and one Playwright test, then PostgreSQL starts under Docker and the Playwright browsers are available, and both tests run.

## Scope

- packages/tooling (the Tooling layer)
- packages/domain (the Domain layer)
- packages/contracts (the Contracts layer)
- packages/data (the Data layer)
- apps/api (the Services layer)
- packages/ui (the Components layer)
- apps/web (the Screens layer)
- apps/e2e (the Black-box tests layer)

## Out of scope

- Anything a later story builds on top of this.
