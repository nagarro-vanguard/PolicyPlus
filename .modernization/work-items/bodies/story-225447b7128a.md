# Remove a selected value or key by deletion entry or clearing

## Story

As a person using the product, I want let a person mark the value they have selected for deletion, so the policy file keeps an instruction that removes it on the machine., so that the file keeps a deletion instruction the machine follows when policies are applied, instead of silently losing the value..

## Context

This ports behaviour of the existing product, described in the attachment: 5 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Hold a policy file's settings in memory and answer questions about them.

## Acceptance criteria

**AC-1: The file does not erase it but replaces it.**
Given a value is deleted from the list, when the person confirms, then the file does not erase it but replaces it with a deletion entry named "**del." followed by the value's name.

**AC-2: The value is removed on that machine.**
Given a value has been replaced by a deletion entry, when policies are applied on the machine, then the value is removed on that machine.

**AC-3: None is chosen, and confirming with none chosen does.**
Given the delete dialog for a key has just opened, when the person looks at the choices, then none is chosen, and confirming with none chosen does nothing.

**AC-4: The choice is accepted without further input, all values.**
Given the person chooses to clear everything, when they confirm, then the choice is accepted without further input, all values of the key are removed and the key is marked cleared.

**AC-5: The key is marked cleared and only the direct.**
Given the person chooses to clear first, when they confirm, then the key is marked cleared and only the direct values it already held are put back.

**AC-6: Those deletion entries are lost and the values of.**
Given the key holds deletion entries or keys inside it with values, when the person clears first, then those deletion entries are lost and the values of the keys inside it are not put back.

**AC-7: The value name box can be typed in; when.**
Given the delete dialog is open, when the option to delete one value is chosen, then the value name box can be typed in; when any other option is chosen, then it cannot be typed in.

**AC-8: It is refused and they are told "You must.**
Given the person chooses to delete one value and leaves the name empty, when they confirm, then it is refused and they are told "You must enter a value name.".

**AC-9: The choice is accepted and any value of that.**
Given the person chooses to delete one value and types a name, when they confirm, then the choice is accepted and any value of that name, whether or not it exists, is removed and replaced by a deletion entry.

**AC-10: Nothing in the file changes.**
Given the delete dialog is open, when the person cancels or presses Escape, then nothing in the file changes.

## Terminologies

- Deletion entry: A value named "**del." followed by the value name, which removes that value on the machine when policies are applied; it is not the same as forgetting the value, which leaves nothing in the file.
