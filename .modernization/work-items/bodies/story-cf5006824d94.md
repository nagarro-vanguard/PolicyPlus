# Look up an identifier as it is typed

## Story

As a person using the product, I want typing an ID in Find by ID looks it up as a category, product, support definition or policy and shows what was found, with the section a policy ID names., so that administrators who know an ID reach the exact item without browsing..

## Context

This ports behaviour of the existing product, described in the attachment: 3 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Confirm Find by ID and limit the area and selection choices.

## Acceptance criteria

**AC-1: A category is tried first,.**
Given text typed in Find by ID, when it is trimmed and looked up, then a category is tried first, then a product, then a support definition, then a policy; the first kind that matches is selected with its own icon, and a policy is looked up only when no other kind matches.

**AC-2: Nothing is selected and a "not found" icon is.**
Given the text matches nothing, when it is typed, then nothing is selected and a "not found" icon is shown; given the text is empty, a blank icon is shown; and a section from an earlier match is not cleared when the text changes to a non-policy.

**AC-3: It means the user or computer section; with no.**
Given a policy ID, when it ends with "@U" or "@C", then it means the user or computer section; with no suffix or any other suffix it applies to both, and the suffix is cut off before the lookup.

**AC-4: The status icons come from the product's icon set.**
Given Find by ID opens, then the status icons come from the product's icon set and the ID box is focused and empty.

## Terminologies

- Find by ID: The lookup of one item by its identifier; it is not a text search.

## Out of scope

The other tasks of this part of the product have their own stories: Confirm Find by ID and limit the area and selection choices.
