# Judge whether a support definition is met by the chosen products

## Story

As a person using the product, I want a support definition lists the products a policy is supported on. The system judges whether a support entry or a whole support definition is met by the products a person has chosen, counting version ranges and nested definitions., so that know whether the products a person has chosen are covered by a support definition..

## Context

## Acceptance criteria

**AC-1: The entry is met; given a product with versions.**
Given a support entry for a product that is not a version range, when that exact product is among the chosen products, then the entry is met; given a product with versions beneath it, when any of those versions or their sub-products is chosen, then the entry is met even if the product itself is not chosen.

**AC-2: It is met, the range running from the entry's.**
Given a support entry for a product that has versions beneath it, whether a version range or a plain entry for a parent product that is not itself chosen, when any version in its range or a sub-product directly beneath one is chosen, then it is met, the range running from the entry's minimum (0 if none) to its maximum (the highest version if none); a range entry never matches on its own product, and a product with no versions beneath it never matches this way.

**AC-3: Every entry must be met, and any other definition.**
Given any-of matching is asked for, when a support definition requires all of its entries, then every entry must be met, and any other definition needs one entry met; given any-of matching is not asked for, then one met entry meets every definition, all-of included; a definition with no entries, or none met, is met only when all are required, and plain product entries are checked before nested definitions.

**AC-4: It counts as not met, including when two entries.**
Given a support definition that has already been met once in one judgement, when it comes up again, then it counts as not met, including when two entries point at the same definition with no cycle.

**AC-5: It counts as supported only if unlisted policies are.**
Given a policy that lists no supported-on information, or a support entry that names no known product, when it is judged, then it counts as supported only if unlisted policies are allowed.

## Terminologies

- Support definition: A named list of products and nested definitions that says what a policy is supported on; not a single product.
- Chosen products: The products the person has ticked as the ones that matter when judging support.
- Any-of matching: A way of judging in which a definition that would normally need every entry needs only one; it applies only when it is asked for.
- Unlisted policies allowed: A choice that lets a policy count as supported when it lists no supported-on information.
