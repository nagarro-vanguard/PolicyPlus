# Use the downloaded definitions as the program's definitions

## Story

As a person using the product, I want from the Help menu the person opens the download window and, after a successful download, the program discards what was loaded, loads the downloaded definitions, remembers them as the definitions to use and redraws its views., so that so the new definitions are in use at once and are the ones the program starts with next time..

## Context

This ports behaviour of the existing product, described in the attachment: 1 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Show the category tree and the list of a chosen category; Link loaded definitions into categories, products and policies; Work out whether a policy is enabled or disabled from its values; Refuse invalid template files with clear messages; Show a policy's state and comment per area; Read policies, products and options from template files; Read and list values in policy files and registry policy keys; Read settings screen layouts from language files; Detect the Group Policy edition and read optional attributes; Decide whether a policy's support rules are met; Show category and policy details and keep the list tidy; Decide whether a policy is enabled, disabled or unsupported; Validate template and language files while reading them; Read support rules, products, classes and list options from templates; Filter policies and keep search results; Refuse operations a REG file source cannot support; Load policy templates from an uploaded package with the right language; Read and write policy files with a byte-faithful round trip; Open policy sources from imported files and describe them.

Open points, to settle before it is built:
- Where do the remembered choices of where policy settings are kept, and the policy file created when none exists, belong now that the program runs on a server?

## Acceptance criteria

**AC-1: The loaded definitions and previous search results are discarded.**
Given the person chooses Acquire ADMX Files, when the download window closes with new definitions, then the loaded definitions and previous search results are discarded and the views are rebuilt from the downloaded ones; when it closes with no new definitions, then nothing has changed.

**AC-2: It uses them as the definitions, as a saved.**
Given the downloaded definitions are loaded, when the program is next opened, then it uses them as the definitions, as a saved choice of the stored definitions rather than of a folder.

**AC-3: It clears what was loaded and uses the default.**
Given the program starts and the remembered definitions cannot be loaded, when it falls back, then it clears what was loaded and uses the default definitions instead of a chosen package.

**AC-4: The person is told and the program goes back.**
Given the program starts and the place the person last chose to keep policy settings cannot be used, when it starts, then the person is told and the program goes back to its default place for policy settings.

**AC-5: The program remembers it for next time.**
Given the person picks a place to keep policy settings, when the choice is accepted, then the program remembers it for next time.

**AC-6: The program remembers that and does not show the.**
Given the person has not yet accepted the warning about editing policy files directly, when they accept it, then the program remembers that and does not show the warning again.

**AC-7: A new empty file is created, so no policy.**
Given a policy file chosen as a source does not exist yet, when the program opens it, then a new empty file is created, so no policy in it is configured.
