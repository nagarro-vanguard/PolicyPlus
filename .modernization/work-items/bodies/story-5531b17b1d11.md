# Set up end-to-end tests with accessibility scans

## Problem

- Stories are proven by behaviour, accessibility is a gate and tests stay deterministic without Windows.

## Goal

- A Playwright suite that drives the running product with stand-in Windows carriers, scans every page and finds elements the way a person does.

## Acceptance criteria

- Given a story's acceptance criteria, when its test is committed, then it is committed before the code and fails first.
- Given the suite runs, when it starts, then it uses the real service with the stand-in Windows carriers.
- Given any page visited in a test, when it is scanned for accessibility, then any violation fails the test.
- Given an element a test uses, when it is found, then it is selected by role and accessible name and not by style class or test id unless it has no role.

## Scope

- packages/contracts (the Contracts layer)
- packages/domain (the Domain layer)
- packages/database (the Database layer)
- apps/api (the API service layer)
- packages/ui (the UI components layer)
- apps/web (the Web app layer)
- apps/e2e (the End-to-end tests layer)
- packages/tooling (the Tooling layer)

## Out of scope

- Anything a later story builds on top of this.
