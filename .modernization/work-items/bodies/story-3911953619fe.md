# Read typed numbers within the 32-bit and 64-bit limits

## Problem

- People cannot store a number a registry value cannot hold, and typing mistakes never silently change a value.

## Goal

- Numbers typed for a registry value are read as decimal or marked hexadecimal and held to the range of a 32-bit or 64-bit value.

## Acceptance criteria

- Given a number entered for a registry value, when it is read, then it is limited to 0 to 4,294,967,295 for a 32-bit value and to 0 to 18,446,744,073,709,551,615 for a 64-bit value.
- Given a typed hexadecimal number, when it is too large to fit then the value is set to the largest allowed value, and when the text is not a hexadecimal number the value is left unchanged.

## Scope

- packages/contracts (the Contracts layer)
- packages/domain (the Domain layer)
- packages/database (the Database layer)
- apps/api (the API service layer)
- packages/ui (the UI components layer)
- apps/web (the Web app layer)
- apps/e2e (the End-to-end tests layer)
- packages/tooling (the Tooling layer)

## Out of scope

- Anything a later story builds on top of this.
