# Match policies to the registry key and value terms entered

## Story

As a person using the product, I want a policy is shown as a match when at least one setting it reads or writes meets every term the person entered, using wildcard, prefix, whole-name and path-part matching., so that the person gets the policies that control the setting they named, whether they gave the key, the value name or both..

## Context

This ports behaviour of the existing product, described in the attachment: 5 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Work out categories, products, policies and the...: Policy option reader.

Open points, to settle before it is built:
- Should matching policies appear as soon as usable terms are entered, with no separate request to search? The rules state that a search starts when the person asks.

## Acceptance criteria

**AC-1: The policy matches if at least one setting meets.**
Given a policy reads or writes several settings, when terms are entered, then the policy matches if at least one setting meets every term, and capital or small letters make no difference.

**AC-2: Only policies with a setting whose value name equals.**
Given a value-name term without "*" or "?", when policies are searched, then only policies with a setting whose value name equals the term as a whole match; with "*" or "?" those act as wildcards over the whole name.

**AC-3: Policies whose key path starts with that text match.**
Given a key term with a backslash and no wildcard, when policies are searched, then policies whose key path starts with that text match.

**AC-4: Policies whose whole key path fits that pattern match.**
Given a key term with "*" or "?", when policies are searched, then policies whose whole key path fits that pattern match.

**AC-5: Policies having a key path with a part equal.**
Given a key term with no backslash and no wildcard, when policies are searched, then policies having a key path with a part equal to that text match.

## Out of scope

The other tasks of this part of the product have their own stories: Judge whether a support definition is met by the chosen products; Reopen the last search results without a new search; Show the limit in force and switch it on or off; Find policies by the words you remember; Refuse unusable registry terms and start the search when asked.
