# Build the shared interface components with Storybook

## Problem

- One visual language and proven accessibility across all screens.

## Goal

- A library of shared screen components that take data and callbacks only, shown in Storybook, using the approved design tokens.

## Acceptance criteria

- Given a component, when it is used, then it takes data and callbacks only and never calls the service or the router.
- Given a component, when Storybook is opened, then a story covers each of its states and an accessibility scan of it passes.
- Given a style, when it is added, then it uses the Tailwind 4 tokens and shadcn on Base UI primitives and adds no new colour, spacing or icon set.

## Scope

- packages/contracts (the Contracts layer)
- packages/domain (the Domain layer)
- packages/database (the Database layer)
- apps/api (the API service layer)
- packages/ui (the UI components layer)
- apps/web (the Web app layer)
- apps/e2e (the End-to-end tests layer)
- packages/tooling (the Tooling layer)

## Out of scope

- Anything a later story builds on top of this.
