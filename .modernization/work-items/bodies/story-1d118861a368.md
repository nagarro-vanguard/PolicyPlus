# Open the download window and name where the definitions go

## Story

As a person using the product, I want a person opens the window for getting Microsoft's policy definitions and sees where the downloaded definitions will be kept, with the same fixed starting point every time., so that so a person who lacks the full set of policy definitions can start the download from a window that is always ready and needs no folder knowledge..

## Context

This ports behaviour of the existing product, described in the attachment: 2 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Stop a second download and closing while a download runs.

## Acceptance criteria

**AC-1: It shows that Microsoft's package will be kept as.**
Given the person opens the download window, when it appears, then it shows that Microsoft's package will be kept as the program's policy definitions, the same each time it opens, and no new set of definitions is offered to the screen that opened it until a download has finished and the person agrees to use it.

**AC-2: There is none: the service reads no folder of.**
Given the window is open, when the person looks for a folder to choose, then there is none: the service reads no folder of the person, so the destination cannot be replaced by choosing one and cancelling changes nothing.

## Terminologies

- Policy definitions: The template files, with their language files, that describe every policy the program can show; not the policy settings a person has chosen.

## Out of scope

The other tasks of this part of the product have their own stories: Stop a second download and closing while a download runs; Download and install Microsoft's policy definitions.
