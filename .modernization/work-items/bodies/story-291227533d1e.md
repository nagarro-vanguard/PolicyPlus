# Show a policy's semantic text on request

## Story

As a person using the product, I want let someone ask for the semantic text of a policy, written one section per area the policy applies to, only when they want it., so that the written form of a policy's settings is detail most readers do not need, so it is shown only on request..

## Context

This ports behaviour of the existing product, described in the attachment: 6 rules it must keep and the reading of the code behind them.

Open points, to settle before it is built:
- Should semantic text that holds a quote or a line break that cannot be read back be flagged to the person, as the step describes, and in what words?

## Acceptance criteria

**AC-1: There is one section per area it applies to,.**
Given a policy that applies to computers, users or both, when someone asks for its semantic text, then there is one section per area it applies to, reading that area's stored settings and comment, and an area the policy does not cover is left out.

**AC-2: Its heading line starts with C for a computer.**
Given a section of semantic text, when it is written, then its heading line starts with C for a computer policy or U for a user policy, followed by the policy identifier.

**AC-3: Its settings and option values are left out; given.**
Given a policy that is not Enabled, when its semantic text is written, then its settings and option values are left out; given it is Enabled, then they are listed.

**AC-4: The comment appears in that section; given none is.**
Given a policy with a stored comment, when its semantic text is written, then the comment appears in that section; given none is stored, then no comment appears.

**AC-5: A whole number has a leading #, an unsigned.**
Given option values in semantic text, when they are written, then a whole number has a leading #, an unsigned number is plain digits, yes/no is True or False, text sits between single quotes, an empty list reads 'None', a list of text is bracketed with one double-quoted item per line and any quote inside an item is doubled, and a table is bracketed as double-quoted name: value lines.

**AC-6: The text is written between single quotes with no.**
Given text option values that hold a quote or a line break, when the semantic text is written, then the text is written between single quotes with no escaping, so it cannot be read back correctly.

**AC-7: Each backslash is doubled and each carriage return plus.**
Given a comment with backslashes or Windows line breaks, when the semantic text is written, then each backslash is doubled and each carriage return plus line feed pair is written as \n, while a lone line feed or lone carriage return is written as it is.

**AC-8: The comment is split over two script lines and.**
Given a comment holding a lone line feed or a lone carriage return, when the semantic text is written, then the comment is split over two script lines and is corrupted when read back.

## Terminologies

- Semantic text: The written form of a policy's settings, one section per area, that can be moved in and out of the program; it is not the registry file form.
