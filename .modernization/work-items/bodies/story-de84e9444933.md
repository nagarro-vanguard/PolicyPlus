# Show a policy's state and comment per area

## Problem

- Administrators scan the policy list for what is configured, so state, comment and state filters must read the same way everywhere.

## Goal

- Build the shared rules that read a policy's state and comment in the user and computer areas, combine them when both areas are shown, and filter the list by state.

## Acceptance criteria

- Given a policy and an area, when its state is read, then it reads Enabled, Disabled, Not Configured or Unknown, from the computer source for the computer area and the user source for any other.
- Given both areas are shown and the policy applies to both, when the states are shown, then the common state is followed by "(2)" when they match, the computer state by "(C)" when only the user is Not Configured, the user state by "(U)" when only the computer is Not Configured, and "Mixed" otherwise.
- Given a state filter is chosen and an area is checked, when the list is filtered, then each policy's state is read in the checked area and only policies whose state matches remain: Configured keeps policies that are Enabled or Disabled, Not Configured keeps those that are Not Configured, and Disabled or Enabled keep only that state.
- Given a policy and an area, when its comment is read, then it is empty when the source has no comment file or no comment for the policy, and otherwise the saved text.
- Given both areas are shown, when the comment column is filled, then it is empty if neither area has a comment, shows "(multiple)" if both do, and otherwise shows the single comment.

## Scope

- packages/tooling (the Tooling layer)
- packages/domain (the Domain layer)
- packages/contracts (the Contracts layer)
- packages/data (the Data layer)
- apps/api (the Services layer)
- packages/ui (the Components layer)
- apps/web (the Screens layer)
- apps/e2e (the Black-box tests layer)

## Terminologies

- Policy state: Enabled, Disabled, Not Configured or Unknown for one area; not the policy's options.

## Out of scope

- Anything a later story builds on top of this.
