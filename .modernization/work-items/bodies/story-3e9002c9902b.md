# Load the chosen folder, replacing or adding to what is loaded

## Story

As a person using the product, I want once a folder is accepted, the workspace empties itself first only when replacing, adds the folder without stopping for problems, tells the person if the load fails, and remembers the folder for the next start only when replacing succeeded., so that so that the person gets their definitions into the workspace in one go, with a sensible default and a clear account of anything that went wrong..

## Context

This ports behaviour of the existing product, described in the attachment: 4 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Load policy definitions from a folder or...: Definition load coordinator.

Open points, to settle before it is built:
- When nothing is loaded, is the person not asked whether to replace? The journey says so, but no rule states it.
- Is the replace choice proposed as the default only when something is loaded? No rule states this beyond the option being ticked by default.

## Acceptance criteria

**AC-1: It is ticked by default.**
Given the replace option is shown in the dialog for loading a folder, when it first appears, then it is ticked by default.

**AC-2: The choice of replacing or not is passed on.**
Given a folder that exists was accepted with OK, when the dialog closes, then the choice of replacing or not is passed on to the load.

**AC-3: No replace choice is passed on.**
Given the person did not accept a folder that exists, when the dialog closes, then no replace choice is passed on.

**AC-4: The workspace is emptied first and the folder's definitions.**
Given replacing was chosen, when the folder loads, then the workspace is emptied first and the folder's definitions are loaded.

**AC-5: Its definitions are added to the current workspace.**
Given replacing was not chosen, when the folder loads, then its definitions are added to the current workspace.

**AC-6: The problems are reported but the load does not.**
Given the folder has problems, when it loads, then the problems are reported but the load does not stop.

**AC-7: The person is told "The folder could not be.**
Given loading the folder fails, when the failure happens, then the person is told "The folder could not be fully added to the workspace." with the reason.

**AC-8: It may be emptied or partly filled and the.**
Given loading the folder fails, when the person looks at the workspace, then it may be emptied or partly filled and the view is rebuilt anyway.

**AC-9: The remembered folder is unchanged.**
Given loading the folder fails, when the person next starts, then the remembered folder is unchanged.

**AC-10: The folder is remembered as the definitions folder for.**
Given replacing was chosen and the load did not fail, when the load ends, then the folder is remembered as the definitions folder for the next start.

**AC-11: The remembered folder is unchanged.**
Given definitions were added to the workspace rather than replaced, when the load ends, then the remembered folder is unchanged.

## Terminologies

- Replace: Emptying the loaded definitions before loading a folder; not adding the folder to what is already loaded.
- Remembered folder: The definitions folder the workspace loads at the next start; not any folder added on top of the loaded set.
