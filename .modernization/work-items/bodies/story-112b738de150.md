# Import a semantic policy into the stored settings

## Story

As a person using the product, I want a person imports SPOL text and its policies are applied to the computer and user settings and their comments, with a result message., so that one import sets many policies at once..

## Context

This ports behaviour of the existing product, described in the attachment: 5 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Show the category tree and the list of a chosen category; Save a policy's state with OK; Work out whether a policy is enabled or disabled from its values; Set, delete and forget values and key clearances in a policy file; Show a policy's state and comment per area; Edit entries of a REG file within its source branch; Read and list values in policy files and registry policy keys; Apply option values to a policy and keep the dialog open; Forget a policy and list the registry values it touches; Decide whether a policy's support rules are met; Open policy sources from imported files and describe them; Replace live registry changes with the registry source model; Read and write the stored form of values in a policy file; Show category and policy details and keep the list tidy; Decide whether a policy is enabled, disabled or unsupported; Filter policies and keep search results; Refuse operations a REG file source cannot support; Read and write policy files with a byte-faithful round trip; Read support rules, products, classes and list options from templates; Keep the browser view consistent after view or edit changes.

Open points, to settle before it is built:
- If writing a policy fails, the old program kept the new comment against a half-written policy. Should the new product keep the comment or undo it?
- Should the failure message say which policies failed and why? The old one gave only a count.

## Acceptance criteria

**AC-1: Each policy goes to the machine or user source.**
Given parsed SPOL, when applied, then each policy goes to the machine or user source by its section.

**AC-2: The comment is stored first; an empty comment leaves.**
Given a policy with a comment and a comment store, when applied, then the comment is stored first; an empty comment leaves any existing one alone.

**AC-3: Its earlier settings are wiped and.**
Given a policy, when applied, then its earlier settings are wiped and then the stated state and settings are written.

**AC-4: It is skipped and counted and the rest are.**
Given many policies, when one fails, then it is skipped and counted and the rest are applied; only the failure count is reported.

**AC-5: The person sees "Semantic Policy successfully applied." or "N.**
Given the import finishes, then the person sees "Semantic Policy successfully applied." or "N out of M could not be applied." and the view refreshes either way.
