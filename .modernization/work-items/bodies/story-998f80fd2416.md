# Choose the user policy source

## Story

As a person using the product, I want in the policy sources dialog, the person chooses where the user policies come from: the local Group Policy, a registry path, a POL file, a per-user Group Policy object, a user hive, or Scratch space. Each choice enables only its own boxes and Browse buttons, which lead to the file picker and the two dialogs for a user's object or profile., so that the person can set the user side separately from the computer side and cannot type into a box that does not belong to the chosen source..

## Context

This ports behaviour of the existing product, described in the attachment: 1 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Choose the computer policy source.

Open points, to settle before it is built:
- What is the content of the Local GPO choice on the user side, since decisions 1, 2 and 12 give no file-based replacement for the system's own policy folder?

## Acceptance criteria

**AC-1: The registry path box is usable only with Registry,.**
Given the person selects a user choice, when the dialog updates, then the registry path box is usable only with Registry, the POL file box and Browse only with POL file, the SID box and Browse only with per-user GPO, and the hive path box and Browse only with user hive.

**AC-2: Its result fills the box that belongs to that.**
Given the person presses a Browse button for the user POL file, the user's Group Policy object or the user's profile, when the matching picker or dialog opens, then its result fills the box that belongs to that choice.

## Out of scope

The other tasks of this part of the product have their own stories: Choose the computer policy source; Confirm or cancel the chosen policy sources.
