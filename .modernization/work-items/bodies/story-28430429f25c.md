# Reopen the last search results

## Story

As a person using the product, I want "Search Results" shows the last results again without a new search., so that people revisit results after editing a policy..

## Context

This ports behaviour of the existing product, described in the attachment: 2 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Show the category tree and the list of a chosen category; Work out whether a policy is enabled or disabled from its values; Show a policy's state and comment per area; Read and list values in policy files and registry policy keys; Decide whether a policy's support rules are met; Start a text or registry search from the main window; Show category and policy details and keep the list tidy; Decide whether a policy is enabled, disabled or unsupported; Go to a policy, category, product or support definition by ID; Filter policies and keep search results; Refuse operations a REG file source cannot support; Read and write policy files with a byte-faithful round trip; Keep the browser view consistent after view or edit changes; Read support rules, products, classes and list options from templates; Open policy sources from imported files and describe them.

## Acceptance criteria

**AC-1: The last results reopen and no new search starts.**
Given a search was run, when "Search Results" is chosen, then the last results reopen and no new search starts.

**AC-2: "No search has been run yet, so there are.**
Given no search has been run or it was cleared, when it is chosen, then "No search has been run yet, so there are no results to display." is shown and nothing opens.

## Out of scope

The other tasks of this part of the product have their own stories: Turn the filter on and change it from the main window; Go to a policy, category, product or support definition by ID; Start a text or registry search from the main window; Step to the next search result.
