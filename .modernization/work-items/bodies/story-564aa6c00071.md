# Turn a typed user name into a valid account identifier

## Problem

- People can pick another user's policies by name instead of needing to know a SID, and cannot proceed with an invalid one.

## Goal

- A user name typed in the user dialog is looked up in the directory to give the account's security identifier (SID), and a typed SID is checked before the dialog closes.

## Acceptance criteria

- Given a name typed in the user dialog, when the person presses Search, then it is turned into the account's SID; if it cannot be translated, they are told "The name could not be translated to a SID."
- Given a name typed but no SID, when the person presses OK, then the name is looked up first and the dialog stays open if no SID results.
- Given a SID text, when the person presses OK, then it must be a valid SID or they are told "The SID is not valid. Enter a SID in the lower box, or enter a username in the top box and press Search to translate."; a valid SID is returned and the dialog closes.

## Scope

- packages/contracts (the Contracts layer)
- packages/domain (the Domain layer)
- packages/database (the Database layer)
- apps/api (the API service layer)
- packages/ui (the UI components layer)
- apps/web (the Web app layer)
- apps/e2e (the End-to-end tests layer)
- packages/tooling (the Tooling layer)

## Terminologies

- SID: The security identifier that names one account for Windows; it is not the account's typed user name.

## Out of scope

- Anything a later story builds on top of this.
