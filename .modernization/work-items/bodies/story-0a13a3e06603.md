# Read and write folders and policy files on the person's machine

## Problem

- The program must edit real policy files at fixed Windows paths, which a browser cannot do.

## Goal

- The service reads, lists and writes folders and files (policy files, template folders, export targets) directly so the browser never touches the disk.

## Acceptance criteria

- Given a chosen folder, when the screen asks for its contents, then the service lists and reads them and the web app never reads the disk itself.
- Given a save of a policy file, when it runs, then the content goes to a temporary file that is renamed over the target.
- Given a save that fails part way, when the person looks at the target, then the earlier file is unchanged and the failure is reported.
- Given ADMX and ADML files in the chosen folders, when the definitions are loaded, then the service reads their text and passes it to the domain parsers, which return schema-checked values.
- Given a policy source with a comment file beside it, when comments are read or saved, then the service reads and writes the CMTX file in place and the domain encodes and decodes it.

## Scope

- packages/contracts (the Contracts layer)
- packages/domain (the Domain layer)
- packages/database (the Database layer)
- apps/api (the API service layer)
- packages/ui (the UI components layer)
- apps/web (the Web app layer)
- apps/e2e (the End-to-end tests layer)
- packages/tooling (the Tooling layer)

## Out of scope

- Anything a later story builds on top of this.
