# Configure environments, local database and the build version

## Problem

- Developers and the black-box tests run against the same database version, a missing setting stops the product at start-up, and the displayed version is never a stale committed file.

## Goal

- Validated environment configuration with an .env.example, a Docker Compose file for local PostgreSQL, and a build step that reads the Git version and passes it to the services and screens as a declared Turborepo input.

## Acceptance criteria

- Given Docker is available, when a developer runs the documented compose command, then a PostgreSQL database starts and accepts a connection with the address given in .env.example.
- Given an environment variable listed in .env.example is missing or invalid, when the service or the screens start, then they stop at start-up with a message naming the variable.
- Given a Git checkout, when the product is built, then the Git version is available to the services and screens as a build-time value and no generated version file is added to the repository.
- Given the Git version changes, when Turborepo builds again, then the affected tasks rerun instead of reusing a cached result.

## Scope

- packages/tooling (the Tooling layer)
- packages/domain (the Domain layer)
- packages/contracts (the Contracts layer)
- packages/data (the Data layer)
- apps/api (the Services layer)
- packages/ui (the Components layer)
- apps/web (the Screens layer)
- apps/e2e (the Black-box tests layer)

## Out of scope

- Anything a later story builds on top of this.
