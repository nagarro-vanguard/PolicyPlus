# Load policy definitions from a folder o...: Template file source adapter

## Problem

- People can only browse and edit policies once their definitions are loaded, and they need to know when something in them could not be used.

## Goal

- Read the administrative template and language files from a chosen folder, or add a single template file, and build the policies and categories people browse.

## Acceptance criteria

- Given a folder of template and language files, when the person loads it, then the files are read from that folder and handed on as parsed documents, and the person's own machine is the only place read.

## Scope

- packages/contracts (the Contracts layer)
- packages/domain (the Domain layer)
- packages/database (the Database layer)
- apps/api (the API service layer)
- packages/ui (the UI components layer)
- apps/web (the Web app layer)
- apps/e2e (the End-to-end tests layer)
- packages/tooling (the Tooling layer)

## Terminologies

- Definitions: The administrative template and language files that describe the policies; not the settings people choose.

## Out of scope

- Anything a later story builds on top of this.
