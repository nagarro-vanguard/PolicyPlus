# Export a policy area as a POL file

## Story

As a person using the product, I want the person writes an area's policy settings out as a POL file download., so that a POL file can be copied to a machine or domain that applies it..

## Context

This ports behaviour of the existing product, described in the attachment: 3 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Import a POL file into the user or computer policies; Read and write the stored form of values in a policy file; Set, delete and forget values and key clearances in a policy file.

Open points, to settle before it is built:
- The old program stopped with an unhandled error when one of the three policy locations was missing; what should the person see instead?

## Acceptance criteria

**AC-1: A policy file held by the product is used.**
Given an area is chosen, when the person exports, then a policy file held by the product is used as is, and policy state that came from imported registry files is rebuilt as a new POL file from the three policy locations.

**AC-2: Every value and every sub-key under each of the.**
Given a POL file is rebuilt from registry files, when it is built, then every value and every sub-key under each of the three policy locations is copied with its own data type and environment variables left unexpanded.

**AC-3: The person is told "POL exported successfully."; if it.**
Given the export is done, when it succeeds, then the person is told "POL exported successfully."; if it cannot be saved, they are told "The POL file could not be saved."

## Out of scope

The other tasks of this part of the product have their own stories: Import a POL file into the user or computer policies; Open the raw editor on a policy file after a warning; Export a policy area as a registry file from the main screen; Import a registry file from the main screen.
