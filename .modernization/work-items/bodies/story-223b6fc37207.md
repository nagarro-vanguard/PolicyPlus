# Show the category tree and the policies of the chosen area

## Problem

- People find a policy by walking the categories, so the tree must show the right ones and keep their place as it changes.

## Goal

- Present the categories of the loaded definitions as a tree with icons, visibility, selection, and a choice of user or computer area.

## Acceptance criteria

- Given a category, when its icon is chosen, then it is orphaned first, empty next, and normal otherwise.
- Given empty categories are switched off, when a category has no visible policy and no visible subcategory, then it is not visible; when they are switched on, every category is visible.
- Given the loaded definitions, when the tree is shown, then only visible categories appear, each with its icon and its visible subcategories below it, sorted.
- Given the category shown in the right pane changes, when the tree updates, then its selection follows that category.
- Given the tree is rebuilt from newly loaded definitions, when it finishes, then nothing is selected and the information pane shows the empty state.
- Given a category is selected in the tree, when the person selects it, then it becomes the current category and any selected policy is cleared.
- Given the "Empty Categories" menu, when the person switches empty categories on or off, then the view moves to the nearest visible category.
- Given the area choice, when it is "User", then user policies show; "Computer", computer policies; any other choice, both.
- Given the list is rebuilt, when the earlier policy is still in the category shown and visible, then it is selected and revealed and the earlier top row is put back if the list still has that many rows; otherwise nothing is selected.

## Scope

- packages/contracts (the Contracts layer)
- packages/domain (the Domain layer)
- packages/database (the Database layer)
- apps/api (the API service layer)
- packages/ui (the UI components layer)
- apps/web (the Web app layer)
- apps/e2e (the End-to-end tests layer)
- packages/tooling (the Tooling layer)

## Terminologies

- Empty category: A category with no visible policy and no visible subcategory; not a category that is missing.

## Out of scope

- Anything a later story builds on top of this.
