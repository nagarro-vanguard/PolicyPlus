# Refuse operations a REG file source cannot support

## Problem

- Applying a newer policy file over an older one to a REG file must fail visibly rather than give wrong answers.

## Goal

- Domain rules that make a REG file source fail every read-style request with 'not implemented'.

## Acceptance criteria

- Given a REG file source, when a value is asked for presence, read, checked for deletion or a key's values are listed, then the request fails with 'not implemented'.

## Scope

- packages/tooling (the Tooling layer)
- packages/domain (the Domain layer)
- packages/contracts (the Contracts layer)
- packages/data (the Data layer)
- apps/api (the Services layer)
- packages/ui (the Components layer)
- apps/web (the Screens layer)
- apps/e2e (the Black-box tests layer)

## Out of scope

- Anything a later story builds on top of this.
