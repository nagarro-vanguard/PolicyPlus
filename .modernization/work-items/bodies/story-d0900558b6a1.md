# Prove the journey: Decide where the user and computer policies are ke...

## Problem

- the journey keeps working as the product changes, in the interface the team ships

## Goal

- an acceptance test that does the journey from its first step to its last, as people will do it

## Acceptance criteria

- Given the product is ready, when the test does "Say where the user policies are kept", then offers local files, the system settings store, a policy file, a particular user's policy or a user profile, or an empty scratch space; asks for the detail only for the kind chosen and accepts only policy files of the right type, including one not yet created..
- Given the product is ready, when the test does "Say where the computer policies are kept", then same, for the computer side, without the per-user kinds..
- Given the product is ready, when the test does "Name the user whose own policy object is used, if I chose that", then hands over to naming a user and returns that user's SID..
- Given the product is ready, when the test does "Confirm and start working", then creates both sources; if either cannot be created, says which and why and stays open; otherwise opens them, shows the outcome, and moves to the nearest visible category..
- Given the product is ready, when the test does "Change my mind", then leaves everything as it was..

## Scope

- packages/contracts (the Contracts layer)
- packages/domain (the Domain layer)
- packages/database (the Database layer)
- apps/api (the API service layer)
- packages/ui (the UI components layer)
- apps/web (the Web app layer)
- apps/e2e (the End-to-end tests layer)
- packages/tooling (the Tooling layer)

## Out of scope

- Anything a later story builds on top of this.
