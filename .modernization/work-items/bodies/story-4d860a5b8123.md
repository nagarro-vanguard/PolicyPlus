# Bring the exported settings into the chosen policy source

## Story

As a person using the product, I want once a file and a prefix are settled, the person imports the settings into the chosen policy source: marked keys are cleared, marked values are deleted and the others are saved with the prefix left off their names, and what the person sees is refreshed., so that the settings from the exported file end up in the policy source the person chose, and a failure is reported plainly instead of leaving the person guessing..

## Context

This ports behaviour of the existing product, described in the attachment: 4 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Apply one policy file's changes onto another source; Hold a policy file's settings in memory and answer questions about them.

Open points, to settle before it is built:
- Should a key that does not start with the prefix be refused, or saved under its full name, and is any limit on which parts of the settings store may be written to applied?
- A value of an unrecognised form is applied as an empty value or fails; which of the two should the new import do?

## Acceptance criteria

**AC-1: The key is cleared, the value is deleted and.**
Given a file with a key marked for removal, a value marked for deletion and other values, when the import runs, then the key is cleared, the value is deleted and the other values are saved, in the policy source of the area the person chose, and the view is refreshed.

**AC-2: It is saved without the prefix; a key that.**
Given a key name that starts with the prefix, whatever its letter case, when the import runs, then it is saved without the prefix; a key that does not start with the prefix is saved with its full original name.

**AC-3: The settings are applied straight to the chosen policy.**
Given a file and a prefix, when the import runs, then the settings are applied straight to the chosen policy source with no further confirmation, and if anything fails the person is told only "Failed to import the REG file."

## Out of scope

The other tasks of this part of the product have their own stories: Choose an exported settings file and have its key prefix worked out.
