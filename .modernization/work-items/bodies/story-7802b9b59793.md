# Step to the next search result

## Story

As a person using the product, I want find Next moves to the next visible policy in the results., so that administrators work through hits one by one..

## Context

This ports behaviour of the existing product, described in the attachment: 2 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Show the category tree and the list of a chosen category; Work out whether a policy is enabled or disabled from its values; Show a policy's state and comment per area; Read and list values in policy files and registry policy keys; Decide whether a policy's support rules are met; Decide whether a policy is enabled, disabled or unsupported; Go to a policy, category, product or support definition by ID; Filter policies and keep search results; Refuse operations a REG file source cannot support; Show category and policy details and keep the list tidy; Read and write policy files with a byte-faithful round trip; Read support rules, products, classes and list options from templates; Open policy sources from imported files and describe them.

## Acceptance criteria

**AC-1: It moves to the next currently visible result, skipping.**
Given results, when Find Next is chosen, then it moves to the next currently visible result, skipping hidden ones, and shows "There are no more results that match the filter." when none is left.

**AC-2: Nothing is returned; otherwise it is the result after.**
Given no search has run or the last result has been passed, when the next policy is taken, then nothing is returned; otherwise it is the result after the last chosen one.

## Out of scope

The other tasks of this part of the product have their own stories: Turn the filter on and change it from the main window; Go to a policy, category, product or support definition by ID; Start a text or registry search from the main window; Reopen the last search results.
