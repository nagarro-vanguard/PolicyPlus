# Export a policy source as a registry settings file

## Story

As a person using the product, I want a person names a file and the system exports the policy source being edited, or just the selected branch of it, as a registry settings file. The branch and the prefix are proposed from what is being edited and can be changed. The person is told whether the export worked., so that people can carry the settings they edited to machines and tools that read registry settings files, naming only the file in the usual case..

## Context

This ports behaviour of the existing product, described in the attachment: 9 rules it must keep and the reading of the code behind them.

## Acceptance criteria

**AC-1: The prefix is the current-user root if the user.**
Given the export dialog opens, when it shows its proposals, then the prefix is the current-user root if the user policy source is being edited and the local-machine root otherwise, the branch is the selected key (empty when nothing is selected), and the person can type over either and the text is used as typed; an empty branch exports the whole policy file.

**AC-2: The export is refused and they are told "Please.**
Given no file name is given, when the person asks to export, then the export is refused and they are told "Please specify a filename and path for the exported REG."

**AC-3: The trailing backslash is removed before the branch is.**
Given a branch ending in a backslash is typed, when the export runs, then the trailing backslash is removed before the branch is used.

**AC-4: The file is used as it is.**
Given the source is backed by a policy file, when it is exported, then the file is used as it is.

**AC-5: It is rebuilt as a new policy file from.**
Given the source is backed by the registry (a chosen registry key or a loaded user hive file), when it is exported, then it is rebuilt as a new policy file from the three policy locations of the machine: the policies, the current-version policies and the current-control-set policies.

**AC-6: Every value and sub-key under each of the three.**
Given a registry-backed source, when the policy file is rebuilt, then every value and sub-key under each of the three locations is copied with its own data type and environment variables are left unexpanded.

**AC-7: A removed key has a leading minus sign and.**
Given keys are marked for removal and values for deletion, when the file is written, then a removed key has a leading minus sign and a deleted value is a bare minus sign.

**AC-8: It is shown as an at sign; quotes and.**
Given a value with the default name, when the file is written, then it is shown as an at sign; quotes and backslashes in names and text are escaped.

**AC-9: Text is quoted, a 32-bit number is eight hexadecimal.**
Given values to write, when the file is written, then text is quoted, a 32-bit number is eight hexadecimal digits marked as a number, and any other type (including a 64-bit number, expandable text or multiple strings) is a series of hexadecimal byte values labelled with its type number, except plain binary which has no type number.

**AC-10: It is broken before that point and each broken.**
Given a line that would run past the 78th character, when the file is written, then it is broken before that point and each broken line ends with a backslash.

**AC-11: The person is told "REG exported successfully." and the.**
Given the file is written, when the export ends, then the person is told "REG exported successfully." and the dialog closes; on any failure they are told only "Failed to export REG!" and the dialog stays open so they can retry.

**AC-12: The dialog closes as cancelled. This rests only on.**
Given the dialog is open, when the person presses Escape, then the dialog closes as cancelled. This rests only on the action that closes the dialog as cancelled; no rule states what is or is not written.

## Terminologies

- Registry settings file: A text file of registry keys and values that can be imported on a machine; it is not the binary policy file the person edits.
- Export branch: The part of the policy source that is exported, starting from a key; it is not the whole file unless left empty.
- Registry prefix: The root name written in front of each exported key, such as the current-user or local-machine root; it is not the branch.
