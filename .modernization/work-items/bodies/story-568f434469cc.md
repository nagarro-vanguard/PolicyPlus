# Apply one policy file's changes to another source

## Problem

- Importing a policy file gives the same result as the legacy product.

## Goal

- Apply the entries of a policy file onto another source, including delete and clear instructions and dropped values of an older file.

## Acceptance criteria

- Given an entry, when applied, then it is saved only if its value name is non-empty and does not start with '**'; other marker or empty-named entries are skipped without notice, and a saved value keeps its case and type.
- Given an entry named '**del.' plus a value name, when applied, then that value is deleted using lower-case key and value names; '**deletevalues' deletes each value in its semicolon-separated list likewise.
- Given an entry starting '**delvals', when applied, then the whole key is cleared by its lower-case name, entries being applied in sorted order so clear-all comes before values.
- Given an entry starting '**deletekeys', when applied, then each key in its semicolon-separated list under the entry's key is cleared by lower-case name, removing only that key's own values and not its subkeys.
- Given a newer file applied over an older one, when applied, then values the old file held and the new dropped are forgotten in the target, only under the three policy branches.

## Scope

- packages/tooling (the Tooling layer)
- packages/domain (the Domain layer)
- packages/contracts (the Contracts layer)
- packages/data (the Data layer)
- apps/api (the Services layer)
- packages/ui (the Components layer)
- apps/web (the Screens layer)
- apps/e2e (the Black-box tests layer)

## Out of scope

- Anything a later story builds on top of this.
