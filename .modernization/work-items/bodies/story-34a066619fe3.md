# Set up the preference store with committed migrations

## Problem

- The old program remembered choices in a Windows registry key; the new one needs a store that fits the confirmed architecture and keeps history of every change.

## Goal

- A PostgreSQL store for remembered choices (language, definitions folder, offers considered), changed only through committed migrations and reached through query functions.

## Acceptance criteria

- Given a remembered choice such as the language or the definitions folder, when it is saved and the program restarts, then the same choice is read back from the preference store.
- Given the program runs, when it starts, then it neither reads nor writes the old registry settings key.
- Given a change to the data layout, when it is made, then it exists as a committed migration and no merged migration is edited afterwards.
- Given a query function, when it returns, then it gives plain data in the contract's shape and never a table object.
- Given an empty database, when the migrations are applied and the database tests run, then they pass against a real PostgreSQL.

## Scope

- packages/contracts (the Contracts layer)
- packages/domain (the Domain layer)
- packages/database (the Database layer)
- apps/api (the API service layer)
- packages/ui (the UI components layer)
- apps/web (the Web app layer)
- apps/e2e (the End-to-end tests layer)
- packages/tooling (the Tooling layer)

## Terminologies

- Preference store: The place where Policy Plus remembers a person's own choices, such as language and definitions folder; it is not where policy settings themselves are kept.

## Out of scope

- Anything a later story builds on top of this.
