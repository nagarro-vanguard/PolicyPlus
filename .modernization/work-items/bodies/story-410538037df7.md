# Apply the options chosen in the filter dialog

## Story

As a person using the product, I want pressing OK in the filter dialog builds a filter from the chosen type, state, comment and supported-on options and closes the dialog accepted., so that administrators see only the policies that meet their conditions..

## Context

This ports behaviour of the existing product, described in the attachment: 4 rules it must keep and the reading of the code behind them.

## Acceptance criteria

**AC-1: The filter keeps only managed policies for Policy, only.**
Given a Policy type is chosen, when OK is pressed, then the filter keeps only managed policies for Policy, only unmanaged ones for Preference, and has no policy-type condition for Any.

**AC-2: The filter requires Not Configured, Configured, Enabled or Disabled.**
Given a Current state is chosen, when OK is pressed, then the filter requires Not Configured, Configured, Enabled or Disabled as chosen, and Any sets no state condition.

**AC-3: The filter keeps only commented policies for Yes, only.**
Given a Commented choice, when OK is pressed, then the filter keeps only commented policies for Yes, only uncommented ones for No, and has no comment condition for Any.

**AC-4: The filter records every ticked product and both matching.**
Given Supported on is ticked, when OK is pressed, then the filter records every ticked product and both matching options, and is accepted even when no product is ticked; given it is unticked, any ticks and options are discarded and no support condition applies.

## Terminologies

- Filter: The set of conditions on type, state, comment and supported products that a policy must meet to be listed; it is not a search.

## Out of scope

The other tasks of this part of the product have their own stories: Choose the products a filter requires; Open, reset or cancel the filter dialog.
