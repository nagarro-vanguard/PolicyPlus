# Export a policy area as a registry file from the main screen

## Story

As a person using the product, I want the person chooses an area and the registry file export window opens for that area's policy file., so that settings can be handed to Windows' own registry import..

## Context

This ports behaviour of the existing product, described in the attachment: 1 rules it must keep and the reading of the code behind them.

It relies on behaviour that other stories build first: Start a registry file export of the selected key; Import a POL file into the user or computer policies; Read and write the stored form of values in a policy file; Export a policy area as a POL file; Set, delete and forget values and key clearances in a policy file.

Open points, to settle before it is built:
- The old program stopped with an unhandled error for an unsupported source, unlike Export POL, which told the person; should the web product tell the person here too?

## Acceptance criteria

**AC-1: The area's policy settings, as a POL, are handed.**
Given the person chooses an area, when they export to a registry file, then the area's policy settings, as a POL, are handed to the export window; if they cannot be produced, the person is told what went wrong.

## Out of scope

The other tasks of this part of the product have their own stories: Import a POL file into the user or computer policies; Export a policy area as a POL file; Open the raw editor on a policy file after a warning; Import a registry file from the main screen.
