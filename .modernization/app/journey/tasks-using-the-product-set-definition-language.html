Why this way recommended

The person states the language, the system checks it is well formed and changed, saves it, and offers to apply it now.

Smallest change that keeps every rule while making the apply-now choice part of the same moment.

Trade-off: The person still has to know the code of the language.

  • Policy Definitions Definition language setting
  • Workspace Language code checker, Language change applier

The architecture, modernized

Rules kept and dropped: 3 kept, 0 dropped
  • When the person confirms the language dialog with text that does not split into exactly two parts around a hyphen (for example "en" or "en-US-x"), it is refused with "Please enter a valid language code." and stays open.
  • When the entered language code, spaces trimmed, is exactly equal (upper and lower case count as different, so en-us differs from en-US) to the stored code, taken without trimming, the dialog closes as cancelled.
  • Setting the language saves the new language code at once, then asks "Language changes will take effect when ADML files are next loaded.
