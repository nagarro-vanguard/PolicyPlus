Limit the policy list to policies

Limit the policy list to policies of a chosen type, state, comment status and supported products, and switch that limit on or off.

Switching is quick and non-destructive.

Why this way recommended

Choices narrow the policy list the moment they are made, with no confirm step, and a person can revert or switch the limit off at any time.

Cuts the open, choose, confirm cycle to choosing: results show the effect of each option immediately and the person can undo it.

Trade-off: Every change refilters the list, so rapid changes may feel busy on a large list.

The architecture, modernized

Rules kept and dropped: 15 kept, 1 dropped
  • When the current filter has a supported-on condition, the dialog opens with Supported on ticked, exactly the filter's products ticked and the two matching options set as the filter holds; product branches whose tick differs from their parent are opened.
  • When the current filter has no supported-on condition, the dialog opens with Supported on unticked, both "Match a policy if at least one selected product is supported" and "Match policies with missing or blank support definitions" ticked, and no product ticked.
  • When the filter dialog opens, the Current state choice shows Any if the current filter has no state condition, otherwise Not Configured, Configured, Enabled or Disabled as the filter holds.
  • When the filter dialog opens, the Policy type choice shows Any if the current filter has no policy-type condition, Policy if it keeps only managed policies, and Preference if it keeps only the others.
  • When the filter dialog opens, the Commented choice shows Any if the current filter has no comment condition, Yes if it keeps only commented policies and No if it keeps only uncommented ones.
  • When OK is pressed, the new filter keeps only managed policies for Policy, only unmanaged ones for Preference, and no policy-type condition for Any.
  • When OK is pressed, the new filter requires the chosen state: Not Configured, Configured, Enabled or Disabled; Any sets no state condition.
  • When OK is pressed, the new filter keeps only commented policies for Yes, only uncommented ones for No, and no comment condition for Any.
  • The product requirement box (the product tree and the two matching options) can be used only while Supported on is ticked; it starts unusable.
  • Ticking or unticking a product by hand ticks or unticks every product beneath it to match; changes made by the dialog itself do not spread.
  • When OK is pressed with Supported on ticked, the filter records every ticked product and both matching options; with it unticked, any ticks and options are discarded and no support condition applies.
  • Changing the filter options turns on "Only Filtered Policies" and moves to the nearest visible category.
  • The "Only Filtered Policies" menu switches the filter on or off and moves to the nearest visible category.
  • Reset returns every choice to its default: Any for type, state and comment, Supported on unticked, both matching options ticked and no product ticked.
  • Pressing Escape closes the filter dialog as cancelled and the current filter is unchanged.

Dropped

  • Double-clicking a product checkbox does nothing, so a tick shown always agrees with the tick kept. A double-click quirk of a tree control; the target's product choice keeps what is shown and what is kept the same by design.

Other ways considered: 2
  • Ask what I want to see 6 steps. The system asks short plain questions, such as what kind, what state and whether commented, and only asks about products if the person says products matter. Trade-off: A fixed order of questions is slower for people who know the one option they want.
  • Set up, then apply 5 steps. The person sets the whole limit as a draft, sees what is in force, and applies or discards it as one decision. Trade-off: Keeps the open, choose, confirm cycle, so no fewer steps than today.
