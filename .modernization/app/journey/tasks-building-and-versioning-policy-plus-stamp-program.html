Make each built copy of the program carry

Make each built copy of the program carry the version of the code it was built from.

3 steps today → 2 proposed1 rules kept · 0 droppedBuilding and versioning Policy PlusProposed

Today, read from the codeModernized: Every build stamps itself

1Build or release the program so it reports which version it is.

The build script is run by someone, or by the release workflow, before the program is built.

2Have the version reflect the exact code being built.

The system asks git to describe the current commit: a tag, commit count and short commit name when tags exist, otherwise just a short commit name.

3Get the program to carry that version.

The system replaces the empty version in the generated source file with that description, so the built program carries it. The committed file keeps an empty version.

inferredBuild or release a copy of the program.

The system derives the version as part of building instead of waiting for someone to run a separate stamping step.

splitKnow which code this copy came from.

Separating the recording from the deriving makes it clear the committed record is never changed.

Why this way recommended

The version is worked out from the code by the system every time a copy is built or released, so nobody has to remember to stamp it.

Removes a manual step that can be forgotten, so no released copy can carry an empty version, while keeping the committed record empty and every rule intact.

Trade-off: Every build, even a throwaway one, now carries a version, so the rule that it can also be run by hand must still be offered.
