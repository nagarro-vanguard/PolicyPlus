Write a policy source

Write a policy source, or one branch of it, as an exported set of machine settings.

3 steps today → 3 proposed9 rules kept · 1 droppedEditing policy files directlyProposed

Today, read from the codeModernized: Export what is selected

1Choose the area, or a branch of the file being edited, to export

Hands the policy source to the export step; a registry-backed source is first rebuilt as a policy file.

2Set the destination file, key prefix and branch

Starts the prefix from the user or computer default and the branch from the selected key; an empty branch exports everything.

defaultedSay where to write the exported settings.

Branch and prefix are filled in so only the file is required.

deferredAdjust the branch or prefix only if the default is not what is wanted.

The rare adjustment no longer stands in front of every export.

3Write the registry file

Refuses without a file name, writes the branch with deletion marks, and reports success or failure. Leaving cancels.

mergedReceive the settings file, or back out.

Building and writing are one outcome for the person.

Why this way recommended

The person only names the file; the system proposes the branch and prefix from what is being edited and exports.

Most exports need only a file name; branch and prefix are proposed from what is being edited and can be changed when needed.

Trade-off: Defaults can be wrong for unusual cases, so they must be visible and changeable.

What carries it: Policy File Exchange

The architecture, modernized

Rules kept and dropped: 9 kept, 1 dropped
  • Export to a registry script is refused until a file name is given; the person is told "Please specify a filename and path for the exported REG."
  • The export dialog starts with the selected key as its source branch, or empty when nothing is selected.
  • The registry prefix box in the export dialog starts as HKEY_CURRENT_USER\ when the user policy source is being edited and HKEY_LOCAL_MACHINE\ otherwise.
  • A branch name given as the source of a REG export has any trailing backslash removed.
  • Exporting uses a source backed by a POL file as is.
  • When a POL is built from a registry-backed source, every value and every sub-key under each of the three policy locations is copied with its own data type, with environment variables left unexpanded.
  • Keys marked for removal are written to a REG file with a leading minus sign and values marked for deletion as a bare minus sign.
  • When a REG file is written, a default value is shown as an at sign, and quotes and backslashes in names and text are escaped.
  • When the registry script is written, the person is told "REG exported successfully." and the dialog closes; on any failure they are told only "Failed to export REG!" and the dialog stays open.

Dropped

  • Exporting to a registry file (REG) hands the policy source of the area the person chooses, as a POL, to the export dialog. An unsupported source raising an unhandled error is a defect that no known source reaches; the target reports any problem to the person plainly instead.
Other ways considered: 1
  • Choose, then name 4 steps. Built around the outcome: decide what to export, decide how its keys are named, then name the file. Trade-off: More decisions up front than the proposal-based path.
Evidence from the code: 5 actions, 10 rules
  • Exports a policy source as a registry export (REG) file.
  • Opens the registry file export dialog for the selected key.
  • Lets the person pick the .reg file to write
  • Closes the dialog as cancelled when Escape is pressed
  • Writes the chosen branch of the policy file to a .reg file
