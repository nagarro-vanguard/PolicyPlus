Add a new key

Add a new key, or a new value of a chosen kind, to a policy file.

2 steps today → 3 proposed8 rules kept · 0 droppedEditing policy files directlyProposed

Today, read from the codeModernized: Checked as you type

1Name a new key

Asks for the key name, checks it is valid and not taken under the same parent, and adds it as an empty key, selected in the list.

inferredGive the new key a name and know at once whether it is usableInferred

The person learns of a problem before confirming rather than after.

keptHave the key created and selected

Same outcome as today.

2Add a value to the selected key

Asks for the value name and one of five kinds, then asks for the data and stores it, replacing a value of the same name without warning.

mergedAdd a value by its name and data togetherInferred

Three questions become one, and the kind is no longer asked before there is data.

Why this way recommended

The system checks a key name while it is typed, and a value is added in one pass with its kind worked out from the data.

Cuts the value flow from three questions to one and shows errors early, with every rule still applied.

Trade-off: Working out the kind may guess wrongly, so the person must be able to see and override it.

What carries it: Policy File Exchange
  • Policy File Exchange Key Name Validator, Key Creator, Value Creator, Number Text Reader, Value Data Editor

The architecture, modernized

Rules kept and dropped: 8 kept, 0 dropped
  • A new key name is refused with "The key name is already taken." when a key of that name, ignoring case, already exists under the same parent.
  • A new key name is refused with "The key name is not valid." when it contains a backslash.
  • When the key name dialog is confirmed, the typed name is returned unchecked; when it is cancelled, an empty name is returned, so an empty typed name and a cancel look the same to the caller.
  • Adding a key does nothing when the name is left empty or the dialog is cancelled; otherwise the key is created under the selected key, or at the top level when nothing is selected, as an empty key, and is selected in the list.
  • The new registry value dialog offers the types String, Expandable string, List of strings, 32-bit DWord and 64-bit QWord, and starts on String.
  • Adding a value to the selected key lets the person choose a name and one of five kinds; the starting data is empty text, zero, or an empty list by kind, and the value is stored only if the person then confirms its data.
  • A number entered for a registry value is limited to 0 to 4,294,967,295 for a 32-bit value and to 0 to 18,446,744,073,709,551,615 for a 64-bit value.
  • Editing a value offers a text, number or list-of-text dialog by kind: text kinds (plain and expandable) a text box, 32-bit and 64-bit numbers a number box, lists of text a multi-line box.
Other ways considered: 2
  • Ask what to add 4 steps. One prompted path that first asks whether to add a key or a value, then asks one question at a time. Trade-off: Slowest for someone who already knows what they want.
  • Name, then kind, then data 4 steps. Adding a key is one name; adding a value is a name, a kind, then its data, each asked in turn. Trade-off: Several small questions for a value, and a name error appears only after confirming.
Evidence from the code: 5 actions, 8 rules
  • Asks for a new key name, checks it is valid and free, and adds the empty key to the policy file.
  • Closes the key name dialog as cancelled when Escape is pressed.
  • Puts the cursor in the key name box with its text selected when the dialog appears.
  • Asks for a value name and type, then its data, and adds the value under the selected key.
  • Closes the new value dialog as cancelled when Escape is pressed.
