Remove keys or values from a policy file

Remove keys or values from a policy file, either leaving a deletion instruction for the machine or forgetting them entirely.

2 steps today → 3 proposed6 rules kept · 0 droppedEditing policy files directlyProposed

Today, read from the codeModernized: Straight from the selection

1Mark a value for deletion, or clear a key

Replaces a value with a deletion entry, or on a key offers clear everything, clear first, or delete one value by name; nothing changes until a choice is made.

inferredMark the selected value for deletionInferred

No dialog and no typing for the most common removal.

keptChoose what to do with a selected key

The three outcomes for a key are genuinely different.

2Forget a key or value completely

After confirming for a key, removes the key, its sub-keys, values and marks, or the value and its deletion entry, leaving no deletion behind.

keptForget an entry entirely

Irreversible removal stays confirmed.

Why this way recommended

What is selected tells the system what to do: a value is marked for deletion straight away with its name known, and a key offers its choices.

Makes the common case, marking a value, a single act, while keeping the confirmation on irreversible removal.

Trade-off: The default for a value assumes the person wants a deletion instruction, so forgetting needs a second route.

The architecture, modernized

Rules kept and dropped: 6 kept, 0 dropped
  • Deleting a single value from the list does not erase it from the file: it is replaced by a deletion entry named "**del." followed by the value name, which removes the value on the machine when policies are applied.
  • The value name box in the delete dialog can be typed in only while the option to delete one value is chosen.
  • Deleting a key offers three choices, and OK does nothing until one is chosen; cancelling or Escape changes nothing.
  • When Delete is confirmed with the option to clear the key or to delete all values under it, the choice is accepted without further input; no option is chosen when the dialog opens, and confirming with none chosen does nothing.
  • When Delete is confirmed with the option to delete one value and the value name is empty, it is refused and the person is told "You must enter a value name."; with a name, the choice is accepted.
  • Forgetting a key asks "Are you sure you want to remove this key and all its contents?" and, on Yes, removes the key, all its sub-keys, every value and every clearing mark from the file with no deletion left behind; No changes nothing.
Other ways considered: 2
  • Ask about the machine 3 steps. A plain question about what should happen on the machine leads to the right removal. Trade-off: More steps than the others.
  • Decide the outcome first 4 steps. The person first says whether the machine should be told to remove it or the file should simply forget it, then answers what that needs. Trade-off: Two decisions are still asked of the person.
Evidence from the code: 5 actions, 6 rules
