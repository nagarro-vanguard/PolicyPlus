Why this way recommended

Start with a plain-language summary of what the policy stores and does, and open the technical detail only for the part wanted.

Most people only need the gist, and layering the detail removes the long single read while keeping every rule.

Trade-off: The summary has to be derived and may be wrong where the code is unclear.

What carries it: Policy Definitions, Policy Source, Policy State

  • Policy Source Policy File Entries, Policy Comment Catalog
  • Policy State Semantic Text Writer, Policy State Provider

The architecture, modernized

Rules kept and dropped: 13 kept, 0 dropped
  • The policy inspector shows a "Registry value" line for the policy only when the policy names a registry value.
  • The policy inspector shows a "Client extension" line for the policy only when the policy names a client extension.
  • The policy inspector lists presentation details for the policy whenever it has both a presentation and elements, whatever the elements hold.
  • Choice display names in the inspector are resolved through the definitions file that defines the policy, and choices are numbered from zero in file order.
  • For a list element the inspector states how value names are formed: "User provides value names" when the person names them, a prefix when the element has one, otherwise "No prefix (values named for their data)".
  • In the inspector, a group of affected registry settings with no on or off setting reads "Left implicit" when the policy names a registry value, and "Left to elements" when it names none.
  • The Semantic Policy fragment shows one section per area the policy applies to: the machine section reads the computer source and its comments, the user section reads the user source and its comments; an area the policy does not cover is left out.
  • In semantic policy text, a whole number is written with a leading #, an unsigned number as digits, and a yes/no value as True or False.
  • When a policy is written as semantic policy text, its settings are listed only if the policy is Enabled.
  • A semantic policy text line shows 'C' for a machine policy and 'U' for a user policy, followed by the identifier.
  • Within each section of the fragment, the policy comment is included only when one is stored for that policy, and the option values are included only when the policy is Enabled.
  • When a policy is written as semantic policy text, backslashes in its comment are doubled and each carriage return plus line feed pair is written as '\n'.
  • The inspector copies the selected line to the clipboard only on Ctrl+C with a line selected.
Data it touches: Policy comment, Policy setting
  • Policy comment Owned by Policy Source. Identified by policy name, area.
  • Policy setting Owned by Policy State. Identified by policy name, area.
