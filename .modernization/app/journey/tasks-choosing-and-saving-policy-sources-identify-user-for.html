Name the user account whose own Group Policy

Name the user account whose own Group Policy object is to be the user policy source.

Today, read from the codeModernized: Give a name or an identifier

1Find the account's identifier from a name.

Translates the typed account name to its security identifier and shows it, or says the name could not be translated.

2Confirm the account.

If only a name was given, looks it up first and keeps the choice open when nothing results; requires a valid identifier, otherwise explains what to enter, and returns it when valid.

3Give up choosing an account.

Closes the choice as cancelled.

mergedSay which user I meanInferred

Search, check and cancel need no separate steps.

Why this way recommended

One entry for either a user name or an identifier; the system works out which it is, translates a name itself and confirms the account in one go.

Collapses look-up, check and confirmation into one request while keeping every message the person can meet.

Trade-off: Relies on the directory being reachable to turn names into identifiers.

What carries it: Policy Source
  • Policy Source Directory Account Resolver, User Identification Entry

The architecture, modernized

Rules kept and dropped: 4 kept, 0 dropped
  • A name typed in the user dialog is turned into the account's security identifier (SID) on Search; if the name cannot be translated, the person is told "The name could not be translated to a SID."
  • When OK is pressed, the SID text must be a valid SID or the person is told "The SID is not valid.
  • When OK is pressed with a name typed but no SID, the name is looked up first, and the dialog stays open if no SID results.
  • Pressing Escape closes the user dialog as cancelled.
Other ways considered: 1
  • Choose from known accounts 3 steps. The system offers the accounts it knows and the person picks one, with typing as the fallback. Trade-off: Needs the directory to list accounts, and long lists must be searched.
