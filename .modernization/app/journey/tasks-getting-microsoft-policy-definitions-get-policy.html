Obtain Microsoft's current set of policy definitions

Obtain Microsoft's current set of policy definitions and install them in a folder the program can use.

Why this way recommended

The person asks for the definitions and the system picks the usual folder, installs everything and reports; choosing another folder is an option, not a required step.

The common case needs one request and one answer, and every rule on permissions, replacement, languages, locking and failure is kept.

Trade-off: People who want another folder take one extra, optional step before starting.

The architecture, modernized

Rules kept and dropped: 12 kept, 0 dropped
  • Each time the download window opens, the destination folder is set to the Windows policy definitions folder (the PolicyDefinitions folder under the Windows folder) and no new policy folder is reported to the caller.
  • Starting the download always fetches one fixed Microsoft package, the Windows 11 September 2026 Update (26H2) administrative templates, into a scratch folder under the person's local application data as "W11Admx.msi"; the person cannot choose another version.
  • Before any file is moved, when the folder written in the destination box already exists and the person is an administrator, ownership of it is taken and Administrators are given full control.
  • While a download runs, the start button, close button, destination box and browse button are all disabled, so a second download cannot be started and the destination cannot change; they are enabled again when it ends.
  • When the person closes the download window while a download is running, the close is refused; the window closes only when no download is running.
  • The downloaded package is unpacked with the Windows installer tool; if the tool ends with a non-zero code the download stops with "Failed to extract the package." and the package is kept.
  • The template files are moved into the destination, then the language files for the person's regional format language (the culture of the regional settings, which can differ from the display language) are moved into a folder of that name if the package holds one.
  • When files are moved into a folder, the folder is created if missing and every file already there with the same name is deleted first and then replaced by the new one, with no backup.
  • For an administrator, each folder handed to the file move that already exists, the destination itself and any existing language folder, has its ownership taken; a language folder created during the move instead inherits permissions from the folder above.
  • When any step fails, the person is told "Failed to " followed by the step that failed (create a scratch space, download the package, extract the package, take control of the destination, move the ADMX files, remove temporary files); the window stays open, controls are re-enabled, and no policy folder is reported.
  • After a successful download the scratch folder is deleted, the person is asked "ADMX files downloaded successfully.
  • Choosing a folder in the browse dialog replaces the destination; cancelling the dialog leaves the destination unchanged.
