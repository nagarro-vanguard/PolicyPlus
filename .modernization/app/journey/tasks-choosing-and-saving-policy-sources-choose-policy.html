Decide where the user and computer policies

Decide where the user and computer policies are kept and start working against those sources.

5 steps today → 5 proposed8 rules kept · 0 droppedChoosing and saving policy sourcesProposed

Today, read from the codeModernized: Say where each side lives

1Say which kind of source holds the computer policies and where it is.

Makes available only the location detail that belongs to the chosen kind of computer source; for a policy file, offers files of the policy file type only, including one that does not exist yet.

2Say which kind of source holds the user policies and where it is: a policy file, a registry location, a user's profile hive or a user's own Group Policy object.

Makes available only the location detail that belongs to the chosen kind of user source; offers policy files of the policy file type, and hands the person on to pick a user profile or a user account when those kinds are chosen.

mergedSay where the user policies are kept

mergedSay where the computer policies are kept

keptName the user whose own policy object is used, if I chose that

3Confirm the choices.

Creates the computer and user sources from the choices, falling back to a scratch space when none is chosen; if either cannot be created tells the person why and keeps the choice open, otherwise accepts both.

5See the policies of the newly chosen sources.

Opens the sources, shows the opening result, and moves the view to the nearest visible category, dropping a selected policy that moved or is now hidden.

mergedConfirm and start working

Creating and opening happen when the person confirms, with one report.

4Abandon the choice without changing anything.

Closes the choice as cancelled.

keptChange my mind

Cancelling is always free.

Why this way recommended

The person states the home of the user policies and of the computer policies, giving details only for the kinds that need them, and the system opens both.

Closest to the outcome: decide the two homes and begin, with the system asking for nothing that the choice does not need.

Trade-off: Both choices are made together, so a failure on one side blocks the other until it is fixed.

The architecture, modernized

Rules kept and dropped: 8 kept, 0 dropped
  • The registry path, POL file name, SID and hive path boxes (and their Browse buttons) for the user side are usable only when their own choice is selected.
  • The file picker for a POL file accepts only '.pol' files, allows choosing a file that does not exist yet, and does not ask before an existing file is chosen.
  • The registry path, POL file name and Browse button for the computer side are usable only when their own choice is selected.
  • When OK is pressed, the user source is created from the selected choice: Local GPO, Registry, POL file, per-user GPO (SID typed), user hive (file path typed), or Scratch space otherwise.
  • When OK is pressed, the computer source is created from the selected choice: Local GPO, Registry (path typed), POL file (name typed), or Scratch space when none of the others is selected.
  • After the person chooses policy sources, they are opened with the opening result shown, and the view moves to the nearest visible category.
  • When a view setting changes, the program moves up to the nearest visible category, drops the selected policy if the move happened or the policy is now hidden, then rebuilds the tree and list.
  • Pressing Escape closes the policy sources dialog as cancelled.
Data it touches: Policy setting, Program preference
  • Policy setting Owned by Policy State. Identified by policy name, area.
  • Program preference Owned by Workspace. Identified by preference name.
