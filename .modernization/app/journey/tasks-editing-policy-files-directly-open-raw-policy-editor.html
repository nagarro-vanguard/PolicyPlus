Open a policy file for direct editing

Open a policy file for direct editing of its raw keys and values, with a warning the first time, and leave the editor when done.

Why this way recommended

The system chooses the area when only one is backed by a policy file, shows the warning only to those who have not accepted it, and tells the person what has changed before they leave.

Takes the one question out of the usual case, folds the warning into starting, and gives a risky tool a clear account of what was changed, while every rule stays.

Trade-off: Inferring the area hides the choice from a person who wanted the other area, and the review step is new.

The architecture, modernized

Rules kept and dropped: 13 kept, 0 dropped
  • The section dialog lets a person choose only the sections the caller allows: User and Computer are each usable only when enabled by the caller.
  • In the section dialog, OK does nothing until User or Computer is chosen; then it returns that section and closes.
  • Pressing Escape closes the section dialog as cancelled.
  • Raw POL editing is available only when the user or computer source is backed by a POL file, otherwise the person is told "Neither loaded source is backed by a POL file."; the area chosen is limited to POL-backed sources.
  • The first time raw POL editing is used, the person must accept "Caution!
  • When nothing is selected in the policy file's list, only Add key and Export are available; Add value, Delete value, Edit and Forget are unavailable.
  • When a value is selected in the list, only Forget is always available; Add key, Add value and Export are unavailable, and Edit and Delete value are available only when the value is not already a delete marker.
  • When a key is selected in the list, Add key, Add value, Delete value, Forget and Export are available, and Edit is unavailable.
  • The raw policy file editor lists keys in alphabetical order ignoring case, each followed by its sub-keys indented, then its values in alphabetical order; a value with an empty name (the marker that keeps an empty key) is not listed.
  • A key name in a policy file is listed as a subkey only once, regardless of case, and the requested key itself is never listed.
  • Special deletion entries in a policy file are listed as such: "**deletevalues" as "Delete values" with its data, "**del.<name>" as "Delete value" with the name, and entries starting "**delvals" as "Delete all values".
  • Ordinary values are listed with their content: lists of text joined by spaces, text as it is, 32-bit and 64-bit numbers in decimal, binary data as hexadecimal bytes separated by spaces.
  • Pressing Done (or Enter) closes the raw policy editor as accepted, and pressing Escape closes it as cancelled; there is no Cancel button.

Other ways considered: 2
  • Guided 5 steps. A short prompted path for people who edit policy files rarely: accept the risk, choose the file, learn the vocabulary, then leave. Trade-off: More steps than the others, which a regular user would find slow.
  • Straight to the file 5 steps. The person says which policy file they want to edit, sees the warning once, works in the file, and leaves when done. Trade-off: It still asks the person to pick the area when both are file-backed, and the warning is a hard stop for first-time users.
