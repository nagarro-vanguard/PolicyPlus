Bring a set of policy settings

Bring a set of policy settings in from a semantic policy text and apply them to the computer and user policy sources.

4 steps today → 2 proposed19 rules kept · 1 dropped2 actions droppedChanging policy settingsProposed

Today, read from the codeModernized: Bring in with live check

1Provide the policy text, from a file or typed in, or start again from an empty one.

Shows the whole file text in place of what was there, or after confirmation restores the empty header; discards any earlier result.

2Check that the text is valid.

Reads the text and says how many policy settings it holds or why it is refused, with the line it stopped at; nothing is applied.

mergedBring in the text, from a file or entered.Inferred

Check happens by default instead of being asked for, saving a step.

3Accept the text for applying.

Hands the parsed text on, or refuses invalid text with the reason; leaving without accepting passes nothing on.

4Apply all the settings.

Applies each policy to the computer or user source by its section, wiping its earlier settings first and storing its comment, skipping and counting failures, then says it succeeded or how many could not be applied and refreshes the view.

defaultedApply what was read.

Apply needs no separate check step before it.

Why this way recommended

The system reads the text as soon as it arrives, shows the count or fault at once, and offers to apply only when the text is good.

Fewest steps and a text can never be applied unchecked, while every reading, applying and failure rule stays.

Trade-off: The person cannot apply a text the system has not already accepted, so there is no way to force a partly bad one through.

What carries it: Policy Source, Policy State
  • Policy Source Registry Export Source, Policy Change Applier, Policy Comment Catalog
  • Policy State Semantic Text Reader, Semantic Text Applier, Semantic Text Import Session

The architecture, modernized

Rules kept and dropped: 19 kept, 1 dropped
  • Open File puts the whole chosen file into the text box, replacing what was typed without asking and without checking it; Reset, after a Yes to "Are you sure you want to reset the text box?", restores the header "Policy Plus Semantic Policy" and blank lines.
  • Opening Import SPOL discards any previously parsed SPOL so a cancelled session passes nothing back.
  • Verify reads the SPOL text and reports "Validation successful, N policy settings found." or "SPOL validation failed: " followed by the reason; nothing is applied.
  • A semantic policy script is refused unless its first line is 'Policy Plus Semantic Policy', with the message 'Incorrect signature.'.
  • The state in a semantic policy script must be 'Not configured', 'Enabled' or 'Disabled', regardless of case. Anything else is refused with 'Unknown policy state.'.
  • A setting value in a semantic policy script is read in this order.
  • A comment line in a semantic policy script is recognised without regard to letter case.
  • A comment in a semantic policy script is refused when it ends with a lone backslash, with the message 'Escape sequence started at end of comment.'.
  • A policy header line in a semantic policy script is a user policy only when its first word is exactly 'U'.
  • A bracketed setting in a semantic policy script holds one line per entry.
  • Settings are read only for a policy that is Enabled.
  • A semantic policy script is read in lines separated by carriage return and line feed.
  • When a semantic policy script fails to load, the error gives the line it stopped at, in the form '(Error found on line N.)'.
  • Apply accepts only SPOL text that reads correctly; the parsed file is passed back to the main window.
  • When a semantic policy is applied, the policy's earlier settings are wiped first and then the stated state and settings are written.
  • When a semantic policy is applied, a comment is stored for the policy first, only if one is given and a comment store exists, before the old settings are wiped and the new ones written.
  • A semantic policy script applies each policy to the machine source or the user source by its section.
  • When a semantic policy script is applied to many policies, a policy that fails is skipped and counted, and the rest are still applied.
  • Importing semantic policy applies all its policies to both sources and comments; the person sees "Semantic Policy successfully applied." or "N out of M could not be applied." when some failed, and the view refreshes either way.
