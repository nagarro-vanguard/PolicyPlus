Load a folder of policy definitions

Load a folder of policy definitions into the workspace so its policies can be browsed.

3 steps today → 4 proposed8 rules kept · 0 droppedBrowsing policy definitionsProposed

Today, read from the codeModernized: Load without questions

1Choose where the definitions come from: the Windows folder, the domain's shared folder, or a folder of their own.

Starts on the own-folder choice, offers the domain choice only when the computer is joined to a domain and that shared folder exists, and lets the folder be typed or picked only for the own-folder choice.

2Confirm the choice, or give up.

Refuses a folder that does not exist and stays open; otherwise passes on the folder and whether to clear the workspace first (offered by default). Escape cancels with nothing chosen.

mergedChoose the folder of definitions to load.

Discovering, picking and checking happen together.

deferredSay whether to replace what is already loaded, only when something is loaded.Inferred

The question appears only when it matters.

keptCancel at any time.

Backing out stays available.

3Have the definitions in that folder available to browse.

Empties the workspace first only if asked, adds the folder's definitions, reports problems without stopping, and on failure says the folder could not be fully added. The folder is remembered for the next start only when the workspace was cleared and the load succeeded.

inferredGet the definitions loaded.

The system works out what to do rather than asking for each aspect.

Why this way recommended

The person gives one folder; the system decides replace or add from what is already loaded.

Fewest decisions: one folder, and replace-or-add is asked only when something is already loaded.

Trade-off: Less control by default over replace versus add.

What carries it: Policy Definitions, Workspace
  • Policy Definitions Definition load coordinator
  • Workspace Definitions folder choice validator, Replace option proposer, Folder addition run

The architecture, modernized

Rules kept and dropped: 8 kept, 0 dropped
  • When the ADMX folder dialog opens, 'This folder' is chosen first, and the 'The domain's SYSVOL' choice is available only if the computer is joined to a domain and the folder \\domain\SYSVOL\domain\Policies\PolicyDefinitions exists.
  • The folder box and its Browse button are usable only when the 'This folder' choice is selected.
  • When OK is pressed in the ADMX folder dialog, the folder is the system's Windows PolicyDefinitions folder, the domain SYSVOL folder, or the typed folder, as chosen.
  • The option to clear the workspace before adding the folder is ticked by default, and its choice is passed on only when a folder that exists was accepted.
  • When a definitions folder is opened, the workspace is emptied first only if "clear workspace" is chosen.
  • When opening a definitions folder fails, the person is told "The folder could not be fully added to the workspace." with the reason.
  • A definitions folder is remembered as the definitions folder for the next start only when "clear workspace" was chosen and the load did not fail; when the workspace is added to, the remembered folder is unchanged.
  • Pressing Escape closes the ADMX folder dialog as cancelled, with no folder chosen.
