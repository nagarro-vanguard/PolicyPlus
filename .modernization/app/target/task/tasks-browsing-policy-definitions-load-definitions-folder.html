How it is done today

Worked out from the code, so each step says how sure we are. Marks are yours: what hurts, what is never used, what is wrong.

1. Choose where the definitions come from: the Windows folder, the domain's shared folder, or a folder of their own.

Starts on the own-folder choice, offers the domain choice only when the computer is joined to a domain and that shared folder exists, and lets the folder be typed or picked only for the own-folder choice.

Stated by the code

2. Confirm the choice, or give up.

Refuses a folder that does not exist and stays open; otherwise passes on the folder and whether to clear the workspace first (offered by default). Escape cancels with nothing chosen.

Stated by the code

3. Have the definitions in that folder available to browse.

Empties the workspace first only if asked, adds the folder's definitions, reports problems without stopping, and on failure says the folder could not be fully added. The folder is remembered for the next start only when the workspace was cleared and the load succeeded.

merged 3. Load the definitions.

takes the place of today's 3

Why, and what it keeps

Checking and loading are one outcome.

  • When OK is pressed in the ADMX folder dialog, the folder is the system's Windows PolicyDefinitions folder, the domain SYSVOL folder, or the typed folder, as chosen. A folder that does not exist is refused with "The folder you specified does not exist." and the dialog stays open.
  • When a definitions folder is opened, the workspace is emptied first only if "clear workspace" is chosen. Otherwise the folder's definitions are added to the current workspace. Problems found are reported but do not stop the load.
  • When opening a definitions folder fails, the person is told "The folder could not be fully added to the workspace." with the reason. The workspace may already be emptied or partly filled, the remembered folder is unchanged, and the view is rebuilt anyway.

split 4. Have the folder remembered for next time.

Why, and what it keeps

Remembering is a visible consequence of replacing.

  • A definitions folder is remembered as the definitions folder for the next start only when "clear workspace" was chosen and the load did not fail; when the workspace is added to, the remembered folder is unchanged.
