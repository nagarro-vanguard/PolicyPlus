Work through the hits of a search and pick the policy to open.

Done by person. Today's way, against the ways we propose.

How it is done today

Worked out from the code, so each step says how sure we are. Marks are yours: what hurts, what is never used, what is wrong.

1. Watch the search run and see its hits.

Clears earlier results, tests every policy in turn, adds hits with their category, refreshes progress every 20 policies and reports the totals when finished or cancelled.

Stated by the code

2. Stop a search that is taking too long or no longer wanted.

Cancels the search when asked or when the results are closed, and settles the progress report.

Stated by the code

3. Come back to earlier results without searching again.

Reopens the last results with the previous choice reselected, or says no search has been run.

Stated by the code

4. Pick a hit to open.

Passes the selected policy back, opens it for editing in the current area and moves the list to it.

Stated by the code

5. Move on to the next visible hit.

Takes the next result that is visible, skipping hidden ones, or says there are no more matching the filter.

Stated by the code

Ways we propose

Results as they arrive

recommendedchosenautomate first

Hits appear for the person to work with while the search is still running, so they can open one early, stop when they have enough, and come back to the same results later.

Costs: Results change under the person's hands while the search runs, so the list must keep the person's place.

Recommended because Removes the wait for a finished search: the person starts reviewing at the first hit, and returning to earlier results is automatic.

This way

inferred 1. Watch the policies that match appear as the search goes.

Clears earlier results, starts with a start message, tests every policy in turn, adds each hit with its category in policy order and keeps progress current as it goes.

takes the place of today's 1

Why, and what it keeps

Review can begin at the first hit instead of after the whole search.

  • Starting a search clears earlier results, sets the progress range to the number of policies, and begins on "Starting search".
  • The search tests every policy in turn, and adds every hit to the list with its category name, in the order policies are held.
  • The list and progress are refreshed after every 20 policies: "Searching: checked N policies so far, found M hits".

merged 2. Stop the search once enough has been found, or leave it.

Cancels the search; leaving before it ends marks it as cancelled with progress full.

takes the place of today's 2

Why, and what it keeps

One way to end a search covers both stopping and leaving.

  • Stop, or closing the results window, cancels the search; closing also leaves the label at "Search canceled" with the bar full if the search had not finished.

kept 3. Know how the search ended.

Reports checked policies and hits, or that the search was cancelled, and no longer offers stopping.

takes the place of today's 2

Why, and what it keeps

The outcome is always stated.

  • When a search ends it reports "Finished searching: checked N policies, found M hits", or "Search canceled: ..." if stopped, and the Stop button is disabled.

kept 4. Pick the policy to open from the hits.

Accepts only a chosen hit, remembers its position, opens that policy's editor in the current area and moves the policy list to it.

takes the place of today's 4

Why, and what it keeps

Picking is the point of the task.

  • Go, or a double-click on a result, accepts only when a result is selected; the selected policy is passed back and its position remembered.
  • A search dialog opens either empty or running a new search. When the person picks a result, its editor opens in the current area and the list moves to that policy.

kept 5. Move on to the next hit.

Takes the next hit still shown after the last one chosen, says there are no more when none is left, and returns nothing when no search ran.

takes the place of today's 5

Why, and what it keeps

Stepping through hits is how a list is worked.

  • Find Next moves to the next result that is currently visible, skipping hidden ones, and tells the person "There are no more results that match the filter." when none is left.
  • Taking the next policy returns nothing when no search has run or when the last result has been passed; otherwise it returns the result after the last chosen one.

merged 6. Come back to the last results later.

Shows the previous results without a new search and selects the earlier choice if still present; tells the person when no search has been run.

takes the place of today's 1, 3

Why, and what it keeps

Returning to results needs no separate mode.

  • "Search Results" only reopens the last results and starts no new search.
  • When the results window is reopened, the previously selected result is selected again if it is still in the list.
  • When search results are opened from the main window and no search has been run (or it was cleared), the person is told "No search has been run yet, so there are no results to display." and nothing opens.
What this way leaves out

Pure presentation of a list (column width, drawing); they carry no business rule and the target's own list handles them.

  • Keeps the title column filling the width of the results list.
  • Turns on double-buffered drawing for the results list.
