Why, and what it keeps

One step for every way of getting text in, and no leftover result from an earlier try.

  • Open File puts the whole chosen file into the text box, replacing what was typed without asking and without checking it; Reset, after a Yes to "Are you sure you want to reset the text box?", restores the header "Policy Plus Semantic Policy" and blank lines.
  • Opening Import SPOL discards any previously parsed SPOL so a cancelled session passes nothing back.

kept 2. Know whether the text is good before anything changes.

Reads the text, and states the number of policy settings found or the reason and line it failed on; nothing is applied.

Why, and what it keeps

A fault is found and located before it can cost anything.

  • Verify reads the SPOL text and reports "Validation successful, N policy settings found." or "SPOL validation failed: " followed by the reason; nothing is applied.
  • A semantic policy script is refused unless its first line is 'Policy Plus Semantic Policy', with the message 'Incorrect signature.'.
  • The state in a semantic policy script must be 'Not configured', 'Enabled' or 'Disabled', regardless of case. Anything else is refused with 'Unknown policy state.'.
  • A setting value in a semantic policy script is read in this order. Starting with # is a whole number, and a # value that is not a whole number fails with a conversion message. A plain non-negative number is an unsigned number. 'True' or 'False', in any letter case, is a yes/no value. Text in single quotes is text, and text in double quotes is a list of text. 'None' is an empty list. Anything else is refused with 'Unknown option data format.'.
  • A comment line in a semantic policy script is recognised without regard to letter case. A backslash followed by another backslash is one backslash, and a backslash followed by 'n' is a line break.
  • A comment in a semantic policy script is refused when it ends with a lone backslash, with the message 'Escape sequence started at end of comment.'. A backslash followed by any other character is refused with 'Unknown comment escape sequence' naming it.
  • A policy header line in a semantic policy script is a user policy only when its first word is exactly 'U'. Any other first word, including lowercase 'u' or 'User', is a machine policy. The rest of the line is the policy's identifier. A header with no space after the first word fails with a general index error, with the line number but no reason.
  • A bracketed setting in a semantic policy script holds one line per entry. Entries with one text are a list, entries with two texts are a table of name and value. With no entries the setting is stored with no value. For a list setting, the existing entries are then removed unless the definition keeps other entries, and nothing is written. For any other kind of setting the empty value makes the write fail.
  • Settings are read only for a policy that is Enabled. Lines under Not configured or Disabled are not read as settings but as the next policy's header.
  • A semantic policy script is read in lines separated by carriage return and line feed. A script using line feeds alone is read as one line, so it is refused with the signature message.
  • When a semantic policy script fails to load, the error gives the line it stopped at, in the form '(Error found on line N.)'.

kept 3. Apply the settings.

Accepts only text that reads correctly, writes each policy to the computer or user source by its section, skips and counts those that fail, and reports success or how many could not be applied.

takes the place of today's 4

Why, and what it keeps

The one step that changes anything is separate and explicit.

  • Apply accepts only SPOL text that reads correctly; the parsed file is passed back to the main window. Invalid text is refused with "The SPOL text is invalid: " and the reason.
  • When a semantic policy is applied, the policy's earlier settings are wiped first and then the stated state and settings are written.
  • When a semantic policy is applied, a comment is stored for the policy first, only if one is given and a comment store exists, before the old settings are wiped and the new ones written. If the writing fails, the new comment stays against a half-written policy. An empty comment leaves any existing comment alone.
  • A semantic policy script applies each policy to the machine source or the user source by its section.
  • When a semantic policy script is applied to many policies, a policy that fails is skipped and counted, and the rest are still applied. The caller gets only the number of failures, not which policy or why.
  • Importing semantic policy applies all its policies to both sources and comments; the person sees "Semantic Policy successfully applied." or "N out of M could not be applied." when some failed, and the view refreshes either way.
What this way leaves out

Dismissing a window and selecting text in a box are ways of using a control; backing out is still free because nothing is applied until the person says so (the discard rule is kept).

  • Closes the window as cancelled when Escape is pressed and no text is selected.
  • Selects all text in the box on Ctrl+A.
