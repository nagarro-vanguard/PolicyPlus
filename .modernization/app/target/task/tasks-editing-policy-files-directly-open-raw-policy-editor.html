kept 1. Choose which policy file to edit directly

Offers only the areas backed by a policy file, each only when the caller allows it; tells the person plainly when none is, and goes on only once an area is chosen; leaving the choice changes nothing.

takes the place of today's 2

Why, and what it keeps

Choosing the area is the first thing the person must settle.

  • The section dialog lets a person choose only the sections the caller allows: User and Computer are each usable only when enabled by the caller.
  • In the section dialog, OK does nothing until User or Computer is chosen; then it returns that section and closes.
  • Pressing Escape closes the section dialog as cancelled.
  • Raw POL editing is available only when the user or computer source is backed by a POL file, otherwise the person is told "Neither loaded source is backed by a POL file."; the area chosen is limited to POL-backed sources.

kept 2. Accept, the first time, that direct editing is for advanced users

Shows the caution; a yes is remembered so it is not asked again, a no leaves the editor closed and asks again next time.

takes the place of today's 1

Why, and what it keeps

The warning guards a risky action and must stay.

  • The first time raw POL editing is used, the person must accept "Caution! This tool is for very advanced users. Improper modifications may result in inconsistencies in policies' states." (Yes continues and records the acceptance; No cancels and asks again next time).

kept 3. See the keys and values of the file

Lists keys alphabetically ignoring case, with sub-keys and values beneath, special deletion entries named as such, and ordinary values with their content.

takes the place of today's 1

Why, and what it keeps

The tree is the working view of the file.

  • The raw policy file editor lists keys in alphabetical order ignoring case, each followed by its sub-keys indented, then its values in alphabetical order; a value with an empty name (the marker that keeps an empty key) is not listed.
  • A key name in a policy file is listed as a subkey only once, regardless of case, and the requested key itself is never listed.
  • Special deletion entries in a policy file are listed as such: "**deletevalues" as "Delete values" with its data, "**del.<name>" as "Delete value" with the name, and entries starting "**delvals" as "Delete all values". They cannot be edited or deleted.
  • Ordinary values are listed with their content: lists of text joined by spaces, text as it is, 32-bit and 64-bit numbers in decimal, binary data as hexadecimal bytes separated by spaces. Other kinds show no content.

kept 4. Know what can be done with the item in front of me

Allows only the actions that fit what is selected: a key, a value, a deletion entry or nothing.

takes the place of today's 3

Why, and what it keeps

Unavailable actions are never offered as choices.

  • When nothing is selected in the policy file's list, only Add key and Export are available; Add value, Delete value, Edit and Forget are unavailable.
  • When a value is selected in the list, only Forget is always available; Add key, Add value and Export are unavailable, and Edit and Delete value are available only when the value is not already a delete marker.
  • When a key is selected in the list, Add key, Add value, Delete value, Forget and Export are available, and Edit is unavailable.

merged 5. Finish editing

Leaves the editor; every change already made stays on the loaded policy source and reaches disk only when policies are saved, whether the person finished or backed out.

takes the place of today's 4

Why, and what it keeps

Finishing and backing out do the same thing, so one way out is enough.

  • Pressing Done (or Enter) closes the raw policy editor as accepted, and pressing Escape closes it as cancelled; there is no Cancel button. The caller ignores the answer, so every change made in the editor stays on the loaded policy source either way, to reach disk only when policies are saved.
