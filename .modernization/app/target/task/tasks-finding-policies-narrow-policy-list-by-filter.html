How it is done today

Worked out from the code, so each step says how sure we are. Marks are yours: what hurts, what is never used, what is wrong.

1. Review the limit currently in force.

Shows the current choices for type, state, comment status and supported products, or the defaults when no condition is set.

Stated by the code

2. Choose the conditions the policies must meet.

Makes the product choice available only when supported-on is wanted, spreads a product choice to the products beneath it, ignores double choosing, and can return every choice to its default.

Stated by the code

3. Apply the chosen conditions or leave them unchanged.

Builds the filter from the choices and turns the filtered view on, moving to the nearest visible category, or leaves the filter as it was.

Stated by the code

4. Turn the limit on or off.

Switches whether the filter applies to the lists and moves to the nearest visible category.

Stated by the code

Ways we propose

Live filter

recommendedchosenautomate first

Choices narrow the policy list the moment they are made, with no confirm step, and a person can revert or switch the limit off at any time.

Costs: Every change refilters the list, so rapid changes may feel busy on a large list.

Recommended because Cuts the open, choose, confirm cycle to choosing: results show the effect of each option immediately and the person can undo it.

takes the place of today's 1

Why, and what it keeps

The person starts from what is in force, not a blank form.

  • When the current filter has a supported-on condition, the dialog opens with Supported on ticked, exactly the filter's products ticked and the two matching options set as the filter holds; product branches whose tick differs from their parent are opened.
  • When the current filter has no supported-on condition, the dialog opens with Supported on unticked, both "Match a policy if at least one selected product is supported" and "Match policies with missing or blank support definitions" ticked, and no product ticked.
  • When the filter dialog opens, the Current state choice shows Any if the current filter has no state condition, otherwise Not Configured, Configured, Enabled or Disabled as the filter holds.
  • When the filter dialog opens, the Policy type choice shows Any if the current filter has no policy-type condition, Policy if it keeps only managed policies, and Preference if it keeps only the others.
  • When the filter dialog opens, the Commented choice shows Any if the current filter has no comment condition, Yes if it keeps only commented policies and No if it keeps only uncommented ones.

merged 2. Choose a policy type, state and comment status.

Keeps only managed for Policy, only unmanaged for Preference, the chosen state, and commented or uncommented as chosen; Any sets no condition. The list narrows now.

takes the place of today's 3

Why, and what it keeps

No confirming step; each choice applies as made.

  • When OK is pressed, the new filter keeps only managed policies for Policy, only unmanaged ones for Preference, and no policy-type condition for Any.
  • When OK is pressed, the new filter requires the chosen state: Not Configured, Configured, Enabled or Disabled; Any sets no state condition.
  • When OK is pressed, the new filter keeps only commented policies for Yes, only uncommented ones for No, and no comment condition for Any.

merged 3. Limit by supported products.

Opens product choice only while a support limit is wanted; choosing a product by hand also chooses the products under it, but loading a limit does not spread; records chosen products and both matching options, and accepts a support limit with no product.

takes the place of today's 2, 3

Why, and what it keeps

Product choice appears only when asked for.

  • The product requirement box (the product tree and the two matching options) can be used only while Supported on is ticked; it starts unusable.
  • Ticking or unticking a product by hand ticks or unticks every product beneath it to match; changes made by the dialog itself do not spread.
  • When OK is pressed with Supported on ticked, the filter records every ticked product and both matching options; with it unticked, any ticks and options are discarded and no support condition applies. A filter with Supported on ticked and no product ticked is accepted.
