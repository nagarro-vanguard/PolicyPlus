How it is done today

Worked out from the code, so each step says how sure we are. Marks are yours: what hurts, what is never used, what is wrong.

1. Choose the area and start the import

Applies to the policy source of the chosen area, or from the raw editor to the file being edited, and refreshes the view afterwards.

Stated by the code

2. Pick the registry file

Offers only registry files and guesses the key prefix from the first key, warning if the guess fails or the file holds default values.

Stated by the code

3. Confirm the prefix and import

Refuses without a file or prefix, loads the file and applies it directly to the policy source, saying only that it failed on any error. Leaving cancels.

The system accepts only exported-settings files and remembers the chosen source.

Why, and what it keeps

File and destination are given together instead of in separate steps.

  • Only files of type *.reg are offered by the file chooser when browsing for the REG file.
  • Importing a registry file (REG) applies it to the policy source of the area the person chooses and refreshes the view.

inferred 2. Be told what the file contains and how its keys will be named in the source.

The system checks the file is a genuine export, ignores blank and comment lines, reads keys, removals, deletions and default values, works out the key prefix from the first key, and warns when the file holds default values or the prefix could not be worked out.

takes the place of today's 2

Why, and what it keeps

The system derives the prefix and the warnings instead of making the person type or discover them.

  • A REG file is refused when its first line is not 'Windows Registry Editor Version 5.00', with the message 'Incorrect REG signature'.
  • Blank lines and lines starting with a semicolon in a REG file are ignored.
  • A REG key header starting with a minus sign marks the whole key for removal. Otherwise it opens a key whose values follow.
  • A REG file value line starting with an at sign is the key's default value, with an empty name.
  • In a REG file, a value written as a bare minus sign is a value to delete. A quoted value is text, 'dword:' is a 32-bit number in hexadecimal, and 'hex' is bytes, typed by the number in brackets or binary if none. Data in none of these forms is kept as a value with no data and no type, with no error, and applying it writes an empty value or fails.
  • A REG file is reported as holding default values when any value has an empty name.
  • The prefix of a REG file is guessed from its first key only. For a key starting with 'HKEY_USERS\' it is that hive plus the user identifier. For any other key, including HKEY_CURRENT_USER, it is the hive name alone. A first key with no further backslash gives an empty prefix. A file with no keys gets 'HKEY_LOCAL_MACHINE\'.
  • When a REG file is chosen and the prefix is empty, the prefix is guessed from the file; if the file holds default values, the person is warned "This REG file contains data for default values, which cannot be applied to all policy sources."
  • When the guess fails, the person is only warned "An error occurred while trying to guess the prefix." and the prefix stays empty.
  • A REG key name is shortened by the prefix only when it starts with it, regardless of case. A prefix always ends in a backslash.

deferred 3. Give a prefix only if the system could not decide one.

The system refuses to continue without a file or a prefix and says which is missing.

takes the place of today's 3

Why, and what it keeps

The prefix is asked only in the rare case it is unknown.

  • Import is refused with "Please specify a REG file to import." when no file is named, and with "Please specify the prefix used to fully qualify paths in the REG file." when no prefix is given.

merged 4. Bring the settings into the source.

The system removes marked keys, deletes marked values, saves the others with the prefix removed from names, tells the person only that the import failed if it does, then refreshes what the person sees.

takes the place of today's 1, 3

Why, and what it keeps

Applying and refreshing are one outcome rather than separate actions.

  • When a REG file is applied to a source, a key marked for removal is cleared, a value marked for deletion is deleted and any other value is saved. A key name starting with the prefix is applied without it. A key not starting with the prefix is applied with its full original name, so the registry source would create a key of that name. The source branch limit is not checked.
  • Import loads the REG file with the prefix and applies it straight to the chosen policy source; on any failure the person is told only "Failed to import the REG file."
  • Importing a registry file (REG) applies it to the policy source of the area the person chooses and refreshes the view.

kept 5. Leave without importing.

The system changes nothing.

takes the place of today's 3

Why, and what it keeps

Backing out stays available at every point.

  • Pressing Escape closes Import REG as cancelled.

Guided import

guided

A short prompted path: pick the file, review what was found, confirm the prefix, then apply.

Costs: More steps than the automated path, but each is explained for people who import rarely.
