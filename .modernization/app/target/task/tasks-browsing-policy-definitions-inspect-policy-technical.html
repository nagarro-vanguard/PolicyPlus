    split 2. Read the stored setting.

    Shows the stored value line only when the policy names one and a "Client extension" line only when it names one; affected stored-setting groups with no on or off setting read "Left implicit" when a stored value is named, "Left to elements" otherwise, and always "Left implicit" in a Yes/No element.

    Why, and what it keeps

    Each part of the inspection is a distinct reading, shown as its own step.

    • The policy inspector shows a "Registry value" line for the policy only when the policy names a registry value.
    • The policy inspector shows a "Client extension" line for the policy only when the policy names a client extension.
    • In the inspector, a group of affected registry settings with no on or off setting reads "Left implicit" when the policy names a registry value, and "Left to elements" when it names none. Inside a Yes/No element it always reads "Left implicit".

    split 3. Read the presentation and elements.

    Lists presentation details whenever there is both a presentation and elements, matching each item to the element with the same ID (none for items without an ID; a missing element is reported rather than stopping everything); choice names come from the defining file, numbered from zero; list value names read "User provides value names", a prefix or "No prefix (values named for their data)".

    takes the place of today's 1, 2

    Why, and what it keeps

    Each part of the inspection is a distinct reading, shown as its own step.

    • The policy inspector lists presentation details for the policy whenever it has both a presentation and elements, whatever the elements hold. Each presentation item with an ID is matched to the policy element with the same ID; items without an ID show no element details. When no element has that ID, the inspector stops with an unhandled error.
    • Choice display names in the inspector are resolved through the definitions file that defines the policy, and choices are numbered from zero in file order.
    • For a list element the inspector states how value names are formed: "User provides value names" when the person names them, a prefix when the element has one, otherwise "No prefix (values named for their data)".

    split 4. Read the policy as semantic text.

    Writes one section per area it applies to (C for computer, U for user, then the identifier), with comment only when stored, settings and option values only when Enabled; values are written in the semantic format, with backslashes doubled and CR LF as \n, and text that cannot be read back safely is flagged.

    takes the place of today's 1, 2

    Why, and what it keeps

    Each part of the inspection is a distinct reading, shown as its own step.

    • The Semantic Policy fragment shows one section per area the policy applies to: the machine section reads the computer source and its comments, the user section reads the user source and its comments; an area the policy does not cover is left out.
    • In semantic policy text, a whole number is written with a leading #, an unsigned number as digits, and a yes/no value as True or False. Text is written between single quotes with no escaping, so text holding a quote or line break cannot be read back. An empty list is written as 'None'. A list of text is written in brackets, one double-quoted item per line with quotes doubled. A table is written in brackets as double-quoted name: value lines.
    • When a policy is written as semantic policy text, its settings are listed only if the policy is Enabled.
    • A semantic policy text line shows 'C' for a machine policy and 'U' for a user policy, followed by the identifier.
    • Within each section of the fragment, the policy comment is included only when one is stored for that policy, and the option values are included only when the policy is Enabled.
    • When a policy is written as semantic policy text, backslashes in its comment are doubled and each carriage return plus line feed pair is written as '\n'. A lone line feed or lone carriage return is written as it is, which splits the comment over two script lines and corrupts it when read back.
