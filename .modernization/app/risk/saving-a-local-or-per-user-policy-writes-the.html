Overview / What can go wrong

Saving a local or per-user policy writes the policy file first and the version file second.

  • Data can end up wrong, lost or inconsistent
  • Medium

Why it matters

A failure on the second step, or a malformed version line that truncates the version file, leaves new settings with an old or damaged version, which Group Policy clients use to detect change.

What we found

  • Updating the version file truncates it before reading each version line. A malformed version line stops the save midway and leaves a damaged file, so Group Policy clients may miss the change.
    Capability: Choosing and saving policy sources
  • Saving a local or per-user policy writes the policy file first and the version file second. If the second step fails, new settings carry an old version number that clients use to detect change.
    Capability: Choosing and saving policy sources
  • Saving a local or per-user Group Policy writes the policy file first and the version file second. If the version file holds a non-numeric version, it is emptied first and left with only the lines before the Version line, losing the version and any later lines, and the two files fall out of step.
    Capability: Choosing and saving policy sources
