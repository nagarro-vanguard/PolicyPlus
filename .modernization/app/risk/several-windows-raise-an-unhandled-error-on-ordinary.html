Overview / What can go wrong

Several windows raise an unhandled error on ordinary input

Double-clicking with no row selected, right-clicking with no category, an unnamed list entry, an unreadable import file, a malformed search wildcard, a removed product in a filter, or an inspector item with no match.

  • Failures are hidden, lost or not retried
  • Low

Why it matters

No program-wide handler is set, so the framework's default error dialog appears.

What we found

  • Double-clicking in any of the four lists of the template details window, with no row selected, raises an error in the person's window, because the first selected row is read without checking.
    Capability: Browsing policy definitions
  • Opening the policy inspector for a policy whose presentation lists an item ID that no policy element has stops the inspector with an unhandled error instead of showing what it can.
    Capability: Browsing policy definitions
  • Double-clicking empty space in the loaded ADMX files list, or in the support definitions list after a filter leaves no rows, stops the window with an unhandled error. The products window guards the same action.
    Capability: Browsing policy definitions
  • Confirming the list editor with a named-entry row whose name cell was never filled in stops the dialog with an unhandled error. A never-filled value cell is also returned as an empty entry, as part of the same missing check.
    Capability: Changing policy settings
  • Right-clicking the category tree when no category is selected raises an unhandled error: the program neither opens nor cancels the menu, because the selected node is read without checking it exists.
    Capability: Choosing and saving policy sources
  • Opening a file in the semantic policy import window reads it whole with no error handling. An unreadable or very large file raises an unhandled error and replaces whatever the person typed.
    Capability: Changing policy settings
  • A registry search with a malformed wildcard (such as an unclosed bracket in the key or value) breaks the search. The background task fails uncaught, so the results window stays on "Starting search" with Stop enabled and no reason is shown.
    Capability: Finding policies
  • Opening the filter dialog fails when the current filter holds a product no longer in the loaded policy definitions, because each product is looked up directly. The person cannot open or reset the filter.
    Capability: Finding policies
