Changing policy settings

Set a policy to Enabled, Disabled or Not configured with its options and comment, and move settings in or out as SPOL text.

Risks 10 risks in this code

  • Medium Applying a policy file's held changes to the live registry writes, deletes or clears whatever keys the file names. Only forgetting old values is limited to policy branches, so a crafted policy file, a different route from a REG import, can change other registry keys.
  • Medium Applying a policy, from the settings window or a script, clears its stored values or comment before the new ones are read or written. A failure, such as a drop-down with no choice, leaves the policy empty or half set and reports little.
  • Medium Comment loading and saving failures are hidden. An unreadable comment file silently disables comments for that source, a failed save is dropped so typed comments are lost, and turning on the comment filter then fails with an unhandled error.
  • Medium Enabling a policy with a list option the person never opened writes that option with no list. The list stays empty until the list editor is used or the source holds one, and nothing checks it.
Showing 4 of 10 risks. Show all 10
  • Medium Importing a REG file applies it key by key to the live policy source with no rollback, and a REG source cannot read or forget values. A failure leaves earlier changes in place and the person sees only a general failure message.
  • Medium Importing a REG file applies it to whichever source is open, live registry or policy file, with no check of the keys it names. The branch limit exists only when a REG file is the target, so an import can write, delete or clear keys outside the policy branches.
  • Medium Results of requesting Windows privileges and loading a user registry file are discarded. The person learns a source cannot be saved, or silently gets an empty read-only source, never why. A refused privilege passes silently and fails later with an unrelated error.
  • Medium Values supplied for a policy's settings, by a person or a script, are written without checks. Numbers are forced to unsigned 32-bit and text is stored as given, ignoring any minimum, maximum or length in the definition. A failure leaves earlier settings written, with no undo.
  • Medium When rights or a per-user registry file cannot be obtained, the results are discarded. The person is told a source cannot be modified or saved, never why, and can keep editing an empty in-memory source that is never written.
  • Low Several windows raise an unhandled error on ordinary input: double-clicking with no row selected, right-clicking with no category, an unnamed list entry, an unreadable import file, a malformed search wildcard, a removed product in a filter, or an inspector item with no match. No program-wide handler is set, so the framework's default error dialog appears.
