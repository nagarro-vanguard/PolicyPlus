Business rules (39)

  • A policy's lists of on-values and off-values count as enabled or disabled evidence for each value in them that is present, using the list's own key when it names one.
    On Main · Used by 7 actions
  • A policy with a registry value of its own counts as enabled evidence when that value holds its 'on' value, which is the number 1 when the template gives none, and as disabled evidence when it holds its 'off' value or is marked for deletion when the template gives none.
    On Main · Used by 7 actions
  • For a policy's list elements, a marked-for-deletion list counts as one deleted element, and a list that holds any values counts as a present element and cancels that deletion.
    On Main · Used by 7 actions
  • For a checkbox element: a value marked for deletion counts as one deleted element. Otherwise, each present off value (or off-list value) counts a tenth of a deleted element, and each present on value (or on-list value) counts one present element. A checkbox whose template declares no on value or on list adds no present evidence, even if it holds 1.
    On Main · Used by 7 actions
  • For any other element (number, text, choice, multi-line text), a value marked for deletion counts as a deleted element and a value that is present counts as a present element.
    On Main · Used by 7 actions
  • If any element is present, the elements add their count to the enabled evidence; only when none is present do deleted elements add to the disabled evidence.
    On Main · Used by 7 actions
  • A policy is Enabled when enabled evidence exceeds disabled evidence, Disabled when disabled exceeds enabled, Not configured when there is no evidence either way, and Unclear when both are equal and above zero.
    On Main · Used by 7 actions
  • A value counts as present when: for a deletion marker, it is marked for deletion; for a number, it exists as a whole number and equals the expected number; for text, it exists as text and equals the expected text. A value of the wrong kind is not present.
    On Main · Used by 7 actions
  • When a value is forgotten in a policy file, both the value and its deletion marker are removed, so the policy reverts to not saying anything about it.
    On FindByRegistry, FindResults · Used by 2 actions
  • A value in a policy file counts as present only if it is stored and not marked for deletion.
    On Main · Used by 7 actions
  • Reading a value from a policy file gives nothing when the value is absent or marked for deletion.
    On Main · Used by 7 actions
  • A value in a policy file counts as marked for deletion when a deletion marker names it, when the key has a clear-all marker, or when a delete-values list for the key names it, regardless of case. Entries are examined in sorted order, and a value whose name sorts after the marker is stored as present and cancels the deletion, whenever it was written and whichever marker kind came before.
    On Main · Used by 7 actions
  • Listing the values of a key in a policy file leaves out the marker entries unless the caller asks for them.
    On FindByRegistry, FindResults, Main · Used by 9 actions
  • When a policy file is clearing a key, all values and markers under the key are dropped and a single clear-all marker is stored.
    On FindByRegistry, FindResults · Used by 2 actions
  • When a key's clearance is forgotten in a policy file, every clear-all marker for that key is removed.
    On FindByRegistry, FindResults · Used by 2 actions
  • The registry values a policy touches are its own value, those in its value lists, those of its elements (the whole key for list elements) and those of checkbox and choice sub-lists, each counted once.
    On FindByRegistry, FindResults · Used by 2 actions
  • A REG file cannot be used as a source for asking whether a value is present: the request fails with 'not implemented'. Applying a newer policy file over an older one to a REG file fails this way for any dropped value under a policy branch.
    On Main · Used by 7 actions
  • A REG file cannot be used as a source for reading a value: the request fails with 'not implemented'. Applying a newer policy file over an older one to a REG file fails this way for any dropped value under a policy branch.
    On Main · Used by 7 actions
  • A REG file cannot be used as a source for checking whether a value will be deleted: the request fails with 'not implemented'. Applying a newer policy file over an older one to a REG file fails this way for any dropped value under a policy branch.
    On Main · Used by 7 actions
  • A REG file cannot be used as a source for listing a key's values: the request fails with 'not implemented'. Applying a newer policy file over an older one to a REG file fails this way for any dropped value under a policy branch.
    On Main · Used by 7 actions
  • Text read from a policy file stops at its first empty character, and a multiple-string value ends at its first empty string.
    On Main · Used by 7 actions
  • A REG file cannot be used as a source for forgetting a value: the request fails with 'not implemented'. Applying a newer policy file over an older one to a REG file fails this way for any dropped value under a policy branch.
    On FindByRegistry, FindResults · Used by 2 actions
  • Text stored in a policy file is written in two-byte characters followed by a closing empty character.
    On FindByRegistry, FindResults · Used by 2 actions
  • When a key is cleared in a REG file, the request is ignored if a source branch is set and the key lies outside it. When no branch is set, every key is accepted. Otherwise the key's earlier entries are replaced by a key-removal entry.
    On FindByRegistry, FindResults · Used by 2 actions
  • When a policy is forgotten, the whole key of each of its list elements is cleared and every registry value it touches is dropped from the source, so it reads as Not configured.
    On FindByRegistry, FindResults · Used by 2 actions
  • When a key's clearance is forgotten in a REG file, the key-removal entry is dropped if it exists. The request is ignored if a source branch is set and the key lies outside it. When no branch is set, every key is accepted.
    On FindByRegistry, FindResults · Used by 2 actions
  • A stored policy file value is read back as text for text and expandable text, a 32-bit or 64-bit number for numbers, a list of strings for multiple strings, and raw bytes for every other type.
    On Main · Used by 7 actions
  • When a value is deleted in the live registry and its key does not exist, nothing happens. A missing value is not an error.
    On FindByRegistry, FindResults · Used by 2 actions
  • In the live registry, 'forgetting' a value deletes it, because the registry cannot remember a pending deletion.
    On FindByRegistry, FindResults · Used by 2 actions
  • When a policy lists no supported-on information, it counts as supported only if the caller allows unlisted policies. The same applies to a support entry that names no known product.
    On Main · Used by 7 actions
  • A value in the live registry counts as present when its key exists and, unless the value name is empty, the key lists a value of that name, regardless of case. An empty name means the key itself.
    On Main · Used by 7 actions
  • A support entry for a product counts as met in two cases. The entry is not a version range and that exact product is among the chosen products. Or the product has versions beneath it, and any of those versions or their sub-products is chosen, even when the product itself is not.
    On Main · Used by 7 actions
  • A support entry for a product that has versions beneath it, whether a version range or a plain entry for a parent product that is not itself chosen, counts as met when any version in its range, or a sub-product directly beneath one, is chosen. The range runs from the entry's minimum (0 if none) to its maximum (the highest version if none). A range entry never matches on its own product, and a product with no versions beneath it never matches this way.
    On Main · Used by 7 actions
  • Reading a value from the live registry gives nothing when the key is missing. Signed numbers are returned as the unsigned numbers policies use, and environment variables in text are not expanded.
    On Main · Used by 7 actions
  • A support definition met a second time anywhere in one evaluation counts as not met, because the list of definitions seen is never emptied. Two entries that point at the same definition, with no cycle, make the second one not met.
    On Main · Used by 7 actions
  • When the caller asks for 'any' matching, a support definition whose logic is all-of needs every entry met, and any other definition needs one entry met. When the caller does not ask for 'any', every definition, all-of included, is met by one entry. A definition with no entries, or none met, is met only when all are required. Plain product entries are checked before nested definitions.
    On Main · Used by 7 actions
  • The live registry never reports a value as marked for deletion.
    On Main · Used by 7 actions
  • A registry key counts as a policy key when it is one of the three policy branches (software\policies, software\microsoft\windows\currentversion\policies, system\currentcontrolset\policies) or lies below one, regardless of case.
    On Main · Used by 7 actions
  • Clearing a key in the live registry deletes every value in it but leaves the key and its subkeys. Forgetting a key's clearance does nothing.
    On FindByRegistry, FindResults · Used by 2 actions
