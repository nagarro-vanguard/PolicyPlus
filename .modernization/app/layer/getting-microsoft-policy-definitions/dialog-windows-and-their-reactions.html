Business rules (46)

  • Choosing a folder in the browse dialog replaces the destination; cancelling the dialog leaves the destination unchanged.
    On DownloadAdmx · Used by 1 action
  • When the person closes the download window while a download is running, the close is refused; the window closes only when no download is running.
    On DownloadAdmx · Used by 1 action
  • Each time the download window opens, the destination folder is set to the Windows policy definitions folder (the PolicyDefinitions folder under the Windows folder) and no new policy folder is reported to the caller.
    On DownloadAdmx · Used by 1 action
  • While a download runs, the start button, close button, destination box and browse button are all disabled, so a second download cannot be started and the destination cannot change; they are enabled again when it ends.
    On DownloadAdmx · Used by 2 actions
  • Clearing the search forgets the results, so reopening them reports that no search has been run.
    On Main · Used by 1 action
  • The welcome offer to download policy definitions is considered only once: the first time the window is shown the program records that it has been considered, even when no offer is made, and never considers it again.
    Changes stateOn Main · Used by 1 action
  • When the offer is considered, it is made only if this Windows edition has no Group Policy support and more than two non-empty categories name a parent that is not among the loaded definitions. The person sees "Welcome to Policy Plus! Home editions do not come with the full set of policy definitions. Would you like to download them now? This can also be done later with Help | Acquire ADMX Files."; Yes starts the download dialog.
    On Main · Used by 1 action
  • When files are moved into a folder, the folder is created if missing and every file already there with the same name is deleted first and then replaced by the new one, with no backup. Only files directly in the source folder are moved. A failure part-way leaves some files replaced and others not.
    Changes stateOn DownloadAdmx · Used by 1 action
  • For an administrator, each folder handed to the file move that already exists, the destination itself and any existing language folder, has its ownership taken; a language folder created during the move instead inherits permissions from the folder above. Every moved file, including the template files in the destination, is reset to inherit permissions. A standard user changes no permissions. A failure here ends the download with "Failed to move the ADMX files.", not the take-control message.
    Changes stateOn DownloadAdmx · Used by 1 action
  • Starting the download always fetches one fixed Microsoft package, the Windows 11 September 2026 Update (26H2) administrative templates, into a scratch folder under the person's local application data as "W11Admx.msi"; the person cannot choose another version.
    Changes stateOn DownloadAdmx · Used by 1 action
  • The downloaded package is unpacked with the Windows installer tool; if the tool ends with a non-zero code the download stops with "Failed to extract the package." and the package is kept. When it succeeds, the downloaded package file is deleted.
    Changes stateOn DownloadAdmx · Used by 1 action
  • A category appears in the tree only when it passes the visibility rule; each shown category gets an icon by its kind and carries its visible subcategories below it, and the tree is sorted.
    On Main · Used by 1 action
  • Before any file is moved, when the folder written in the destination box already exists and the person is an administrator, ownership of it is taken and Administrators are given full control. This applies to whatever folder text is in the box, not only the Windows folder; a standard user skips it. A failure ends the download with "Failed to take control of the destination." and nothing is moved.
    Changes stateOn DownloadAdmx · Used by 1 action
  • After the category tree is rebuilt from the loaded definitions, no category, policy or highlighted item is selected and the information pane shows the empty state.
    On Main · Used by 1 action
  • The template files are moved into the destination, then the language files for the person's regional format language (the culture of the regional settings, which can differ from the display language) are moved into a folder of that name if the package holds one. Unless that language is en-US, the English files are also moved into an en-US folder as a fallback; if the package has no en-US folder, the download stops with "Failed to move the ADMX files." after the destination files were already replaced.
    Changes stateOn DownloadAdmx · Used by 1 action
  • When the list is rebuilt, the policy already selected is selected again and revealed only if it is still listed, that is, it sits in the category shown and passes the visibility rule; otherwise nothing is selected. Then, if the policy is in the same category and the list still has that many rows, the earlier top row is put back, so the policy is not guaranteed to stay in view.
    On Main · Used by 1 action
  • The right pane lists the chosen category in this order: an "Up: <parent name>" row marked "Parent" when the category has a parent, then visible subcategories by name, then visible policies by name. Each policy row shows its state and its comment text.
    On Main · Used by 1 action
  • After a successful download the scratch folder is deleted, the person is asked "ADMX files downloaded successfully. Open them now?", and the destination is reported as the new policy folder only if they answer Yes; either answer closes the window as done.
    On DownloadAdmx · Used by 1 action
  • When any step fails, the person is told "Failed to " followed by the step that failed (create a scratch space, download the package, extract the package, take control of the destination, move the ADMX files, remove temporary files); the window stays open, controls are re-enabled, and no policy folder is reported. If only the final cleanup of the scratch folder fails, all files are already installed yet the person is told "Failed to remove temporary files." and no new policy folder is offered.
    On DownloadAdmx · Used by 1 action
  • The category tree selection follows the category shown in the right pane.
    On Main · Used by 1 action
  • When nothing is selected, the title and support lines are hidden and the pane reads "Select an item to see its description.".
    On Main · Used by 1 action
  • For a selected policy the information pane shows its title, "(no requirements information)" when it has no support rule or "Requirements:" plus the support name, and its explanation. A notice that the policy is a preference appears only for preferences.
    On Main · Used by 1 action
  • For a selected or highlighted category the pane shows its title, "This category contains N policies and M subcategories." ("The selected category" when highlighted but not opened) and its explanation. The counts include every policy and subcategory, hidden or not.
    On Main · Used by 1 action
  • A category is orphaned when it has no parent among the loaded definitions although its definition names one.
    On Main · Used by 2 actions
  • A category is empty when it holds no subcategories and no policies at all, counting hidden ones.
    On Main · Used by 2 actions
  • A category's icon is chosen in this order: orphaned, then empty, then normal.
    On Main · Used by 1 action
  • A policy's icon is chosen in this order: preference, then plain when it has no configurable elements, then "extra configuration" when it has some.
    On Main · Used by 1 action
  • A category is visible when empty categories are switched on. Otherwise it is visible only if it has at least one visible policy or one visible subcategory.
    On Main · Used by 1 action
  • A policy is visible only if it applies to a chosen area (user, computer or both). With "Only Filtered Policies" on, it must also pass the filter for a chosen area it applies to; passing for either one is enough.
    On Main · Used by 1 action
  • With both areas shown, a policy that applies to both areas shows its common state followed by "(2)" when both match, the computer state followed by "(C)" when only the user is Not Configured, the user state followed by "(U)" when only the computer is Not Configured, and "Mixed" otherwise.
    On Main · Used by 1 action
  • With both areas shown, a policy that applies to one area shows that area's state followed by "(C)" for computer or "(U)" for user. With a single area shown, only that area's state is shown, without a suffix.
    On Main · Used by 1 action
  • A policy's state in one area reads "Enabled", "Disabled", "Not Configured" or "Unknown"; the computer source is read for the computer area and the user source for any other.
    On Main · Used by 1 action
  • With both areas shown, the comment column is empty when neither area has a comment, shows "(multiple)" when both have one, and otherwise shows the single comment.
    On Main · Used by 1 action
  • A policy's comment in one area is empty when that source has no comment file or holds no comment for the policy, and otherwise the saved text.
    On Main · Used by 1 action
  • A policy is a preference, not a managed policy, when it names a registry key outside the three policy locations: software\policies, software\microsoft\windows\currentversion\policies and system\currentcontrolset\policies.
    On Main · Used by 1 action
  • Closing the workspace or replacing it with a new one discards all loaded definitions and the previous search results.
    Changes stateOn Main · Used by 1 action
  • A filter on managed policies hides preferences when managed policies are wanted, and hides managed policies when preferences are wanted.
    On Main · Used by 1 action
  • A policy passes the filter only when it passes every active part of it.
    On Main · Used by 1 action
  • A filter on state keeps only policies whose state in the checked area is Configured (Enabled or Disabled), Not Configured, Disabled or Enabled, as chosen.
    On Main · Used by 1 action
  • A filter on comments keeps only policies that have a non-empty comment in the checked area, or only those that have none, as chosen.
    On Main · Used by 1 action
  • A filter on products keeps only policies supported by the chosen products, honouring the options to match any product and to include policies with blank support.
    On Main · Used by 1 action
  • A policy applies to an area when its definition declares that area; a policy declared for both applies to each.
    On Main · Used by 1 action
  • When loading definitions reports no problems nothing is shown; otherwise the person sees "Errors were encountered while adding administrative templates to the workspace." with each problem, and, only where a choice is wanted, is asked "Continue trying to use this workspace?".
    On Main · Used by 1 action
  • The language for definition text is the saved language code, or the computer's own language when none is saved.
    On Main · Used by 1 action
  • After a successful download of definitions, the workspace is emptied, the downloaded folder loaded and saved as the definitions folder, and the view rebuilt; with no new folder nothing changes.
    Changes stateOn Main · Used by 1 action
  • The text of a policy description is tidied for display: leading and trailing spaces are removed from every line and blank space at the end of the text is dropped.
    On Main · Used by 1 action
