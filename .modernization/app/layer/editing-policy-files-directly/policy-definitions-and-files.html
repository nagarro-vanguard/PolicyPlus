  • For a checkbox element: a value marked for deletion counts as one deleted element. Otherwise, each present off value (or off-list value) counts a tenth of a deleted element, and each present on value (or on-list value) counts one present element. A checkbox whose template declares no on value or on list adds no present evidence, even if it holds 1.
    On Main · Used by 3 actions
  • When a policy file is read, an extra empty character after the value name, as Microsoft's documentation allows, is skipped.

  • A REG key header starting with a minus sign marks the whole key for removal. Otherwise it opens a key whose values follow.

  • When a policy file is read and the same key and value name occur twice, the later entry wins. Key and value names are matched without regard to letter case, and the first spelling seen is kept for saving.
    On Main · Used by 1 action
  • For any other element (number, text, choice, multi-line text), a value marked for deletion counts as a deleted element and a value that is present counts as a present element.
    On Main · Used by 3 actions
  • A REG file value line starting with an at sign is the key's default value, with an empty name.
    On ImportReg · Used by 2 actions
  • In a REG file, a value written as a bare minus sign is a value to delete. A quoted value is text, 'dword:' is a 32-bit number in hexadecimal, and 'hex' is bytes, typed by the number in brackets or binary if none. Data in none of these forms is kept as a value with no data and no type, with no error, and applying it writes an empty value or fails.
    On ImportReg · Used by 2 actions
  • If any element is present, the elements add their count to the enabled evidence; only when none is present do deleted elements add to the disabled evidence.
    On Main · Used by 3 actions
  • A policy is Enabled when enabled evidence exceeds disabled evidence, Disabled when disabled exceeds enabled, Not configured when there is no evidence either way, and Unclear when both are equal and above zero.
    On Main · Used by 3 actions
  • When a policy file is saved, entries are written in alphabetical order, so a key-clearing marker is always written before the values it clears.
    On Main · Used by 1 action
  • A value counts as present when: for a deletion marker, it is marked for deletion; for a number, it exists as a whole number and equals the expected number; for text, it exists as text and equals the expected text. A value of the wrong kind is not present.

  • When a value is marked for deletion in a policy file, any value or marker already held under that name is dropped first. A deletion marker holding the number 32, as Microsoft does, is added unless the value is already marked or its key is cleared.

  • When a REG file is written, a default value is shown as an at sign, and quotes and backslashes in names and text are escaped. Text is written as quoted text and a 32-bit number as 'dword:' with eight hexadecimal digits. Every other type, including 64-bit numbers, expandable text and multiple strings, is written as hex bytes. Each carries its type number as hex(n), except plain binary, which is written as hex. Lines wrap before column 78 with a trailing backslash.
    On ExportReg · Used by 1 action
  • A value in a policy file counts as marked for deletion when a deletion marker names it, when the key has a clear-all marker, or when a delete-values list for the key names it, regardless of case. Entries are examined in sorted order, and a value whose name sorts after the marker is stored as present and cancels the deletion, whenever it was written and whichever marker kind came before.
    On EditPol, ExportReg, ImportReg, Main · Used by 11 actions

    On ExportReg, Main · Used by 2 actions

    On ExportReg, Main · Used by 2 actions
