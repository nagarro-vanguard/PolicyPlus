Business rules (50)

  • When the policy sources dialog opens with the last-used sources, each side is set to the remembered kind (Local GPO, Registry, POL file, Scratch space, and for users also per-user GPO or user hive), and the registry path, file name, SID or hive path is filled in only for the kinds that carry one.
    On Main · Used by 1 action
  • When the person confirms the language dialog with text that does not split into exactly two parts around a hyphen (for example "en" or "en-US-x"), it is refused with "Please enter a valid language code." and stays open. Any text with exactly one hyphen passes, including "-", "en-" or text with path characters: it is not checked as a real language code. The code is later used as a folder name when looking for ADML files.
    On LanguageOptions · Used by 1 action
  • When the entered language code, spaces trimmed, is exactly equal (upper and lower case count as different, so en-us differs from en-US) to the stored code, taken without trimming, the dialog closes as cancelled. Otherwise the dialog returns the entered code as accepted; saving it is done elsewhere.
    On LanguageOptions · Used by 1 action
  • The program allows secure connections using TLS 1.0, 1.1 and 1.2 only, so downloads use no other protocol.
    On Main · Used by 1 action
  • On first start, when no policy sources were saved, both the user source and the computer source open as the local Group Policy files (Local GPO) with no extra location.
    On Main · Used by 1 action
  • When the previously saved policy sources cannot be opened, the person is told "The previous policy sources are not accessible. The defaults will be loaded." and both sources are saved as Local GPO, then opened quietly. Only the source type is reset; any saved location text stays.
    Changes stateOn Main · Used by 1 action
  • Clearing the search forgets the results, so reopening them reports that no search has been run.
    On Main · Used by 1 action
  • The list of areas starts on "User or Computer", the first choice, so both user and computer policies are shown at start.
    On Main · Used by 1 action
  • The definitions folder to load is the one saved last time; when none is saved it is the Windows PolicyDefinitions folder.
    On Main · Used by 2 actions
  • When loading the saved definitions reports problems, the person is asked whether to keep using the workspace. Yes keeps the partly loaded workspace. No raises the failure "You decided to not use the problematic ADMX bundle.", which goes into the failed-load handling: the workspace is thrown away, and for a non-default folder the person is asked to load the default, while for the default folder the person is told the definitions could not be loaded.
    Changes stateOn Main · Used by 2 actions
  • When the saved folder is not the Windows default and fails to load, the person is told "Policy definitions could not be loaded from "<folder>": <reason> Load from the default location?". Yes saves the Windows default folder as the definitions folder; No leaves the workspace empty with no further message.
    Changes stateOn Main · Used by 2 actions

    On Main · Used by 2 actions
