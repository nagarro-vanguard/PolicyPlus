Import a registry file

Bring a .reg file into the policy source. Built from PolicyPlus/ImportReg.vb

Risks 1 risk in this code

  • Medium Importing a REG file applies it key by key to the live policy source with no rollback, and a REG source cannot read or forget values. A failure leaves earlier changes in place and the person sees only a general failure message.

PolicyPlus/RegFile.vb:42
A REG key header starting with a minus sign marks the whole key for removal. Otherwise it opens a key whose values follow.
PolicyPlus/RegFile.vb:54
In a REG file, a value written as a bare minus sign is a value to delete. A quoted value is text, 'dword:' is a 32-bit number in hexadecimal, and 'hex' is bytes, typed by the number in brackets or binary if none. Data in none of these forms is kept as a value with no data and no type, with no error, and applying it writes an empty value or fails.
PolicyPlus/RegFile.vb:65
Text read from a policy file stops at its first empty character, and a multiple-string value ends at its first empty string.
PolicyPlus/PolicySource.vb:231
The prefix of a REG file is guessed from its first key only. For a key starting with 'HKEY_USERS\' it is that hive plus the user identifier. For any other key, including HKEY_CURRENT_USER, it is the hive name alone. A first key with no further backslash gives an empty prefix. A file with no keys gets 'HKEY_LOCAL_MACHINE\'.
PolicyPlus/RegFile.vb:284

A stored policy file value is read back as text for text and expandable text, a 32-bit or 64-bit number for numbers, a list of strings for multiple strings, and raw bytes for every other type.
PolicyPlus/PolicySource.vb:320
When a policy file is clearing a key, all values and markers under the key are dropped and a single clear-all marker is stored.
PolicyPlus/PolicySource.vb:183
A value in a policy file counts as marked for deletion when a deletion marker names it, when the key has a clear-all marker, or when a delete-values list for the key names it, regardless of case. Entries are examined in sorted order, and a value whose name sorts after the marker is stored as present and cancels the deletion, whenever it was written and whichever marker kind came before.
PolicyPlus/PolicySource.vb:118

PolicyPlus/PolicySource.vb:139
A REG key name is shortened by the prefix only when it starts with it, regardless of case. A prefix always ends in a backslash.
PolicyPlus/RegFile.vb:187
When a value is saved into a REG file, it is ignored if a source branch is set and its key lies outside that branch. When no branch is set, every key is accepted. Any value already stored under that name is replaced.
PolicyPlus/RegFile.vb:226
When a value is deleted in a REG file, the request is ignored if a source branch is set and the key lies outside it, or if the key is already marked for removal. When no branch is set, every key is accepted. Otherwise the value is recorded as deleted.
PolicyPlus/RegFile.vb:240
When a number is saved to the live registry, an unsigned 32-bit or 64-bit number is converted to the signed number the registry stores with the same bits, and the key is created if missing.
PolicyPlus/PolicySource.vb:374
In the live registry, 'forgetting' a value deletes it, because the registry cannot remember a pending deletion.
PolicyPlus/PolicySource.vb:371
When a value is forgotten in a policy file, both the value and its deletion marker are removed, so the policy reverts to not saying anything about it.
PolicyPlus/PolicySource.vb:99
When a REG file is applied to a source, a key marked for removal is cleared, a value marked for deletion is deleted and any other value is saved. A key name starting with the prefix is applied without it. A key not starting with the prefix is applied with its full original name, so the registry source would create a key of that name. The source branch limit is not checked.
PolicyPlus/RegFile.vb:260
Clearing a key in the live registry deletes every value in it but leaves the key and its subkeys. Forgetting a key's clearance does nothing.
PolicyPlus/PolicySource.vb:416
A multiple-string value is stored as its strings each followed by an empty character, with one more empty character closing the list.
PolicyPlus/PolicySource.vb:296
A 64-bit number is stored in a policy file as 8 bytes, lowest byte first.
PolicyPlus/PolicySource.vb:272
When a key is cleared in a REG file, the request is ignored if a source branch is set and the key lies outside it. When no branch is set, every key is accepted. Otherwise the key's earlier entries are replaced by a key-removal entry.
PolicyPlus/RegFile.vb:248
A 32-bit number is stored in a policy file as 4 bytes, lowest byte first.
PolicyPlus/PolicySource.vb:255

PolicyPlus/PolicySource.vb:92
When a value is set in a policy file, it replaces any value already held under that name. A deletion marker for the name is not removed.
PolicyPlus/PolicySource.vb:105

PolicyPlus/PolicySource.vb:240
