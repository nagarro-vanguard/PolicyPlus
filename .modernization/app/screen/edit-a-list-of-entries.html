Business rules for this screen (2)

Dialog windows and their reactions (2)
When the list editor is confirmed for a list where the person names each entry, and two entries have exactly the same name, it is refused with "Multiple entries are named "<name>"! Remove or rename all but one." and nothing is returned. Names are compared exactly, so Run and run are accepted as two entries. A name cell never filled in stops the dialog with an unhandled error.
PolicyPlus/ListEditor.vb:28
When the list editor is confirmed for a list without names, every row except the empty new row at the bottom is returned in the order shown, with no check that a cell has content; a row whose value cell was never filled is returned as an empty entry. For named lists the same new row is ignored.
