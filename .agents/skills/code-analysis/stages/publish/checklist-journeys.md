# Review checklist: The journeys of today

Each task says what a person gets done with the system and how it is done today; whoever designs the better way reads only these tasks, never the code. A task claims every entry point and rule in it (`briefPath`). Open the code an entry point lies in where a claim about it is uncertain.

## Wrong

- A task that is a screen, a control or a layer of the old system rather than something a person gets done, or an outcome that names a control, a page, a window, a command, a medium or a name the code uses.
- A step whose intent or system response the entry points it cites do not show, or one marked `sure` that was concluded rather than read.
- Entry points grouped into one task that serve different outcomes, or one outcome split over tasks where one name covers them; a rule placed in a task whose entry points never reach it.
- An actor that no entry point supports, or `person` where the code names a role.

## Missing

- A step the cited entry points plainly take (a check, a confirmation, a notification, a save) that the journey leaves out.
- A kind of data or outside system an entry point of the task reads, saves or reaches that the task does not list.
- In a joining job: two tasks that are plainly one outcome and stay apart, or two joined that are different outcomes.
