# Review checklist: Inventory

Every later stage reads exactly the code this scope keeps, in the terms of these technologies: How it runs studies each framework and platform named, and the Map reads every line left in. A technology claims what code in scope is built with; a part claims the folders it is built and run from; a fact claims what its lines show, for the person to decide with. In scope means what the manifest lists that the request's Leave Out does not remove; the agent writes no scope rule.

## Wrong

- A technology, kind or version its lines do not show, word for word in each line cited; a version that is not the one the code ships with, for example an assembly's version where the package's is cited.
- A framework or platform How it runs would study for nothing: no code in scope runs on it.
- A part that is not one thing built and run (a folder of helpers, a test project written as a program, a project file with no code of its own), two parts that are one, or a part whose folders hold another part's code; a use naming parts that do not use it at that version; a part of the wrong kind.
- A fact that restates what a part or technology already holds, or answers a question How it runs owns: Inventory's answers are its parts and technologies, and its facts are risks, assumptions, or what the person needs at the checkpoint that no record of it holds. Code that does not read as plain text is already shown at the checkpoint: ask for an assumption only where the agent knows more than the listing, such as an encoding.
- A fact its lines do not show, or one a reader cannot act on: code names in its words, a statement that says nothing the person decides by; an assumption the code settles (read more, and state what it shows), or one with no way to confirm it or no effect if wrong.

## Missing

- Borrowed code still in scope: generated output, installed packages or a copied library, in any copy; say it as an assumption or a fact so the person can extend the Leave Out.
- A framework, platform or library the code in scope is built on, absent because its own copy is left out: the code built on it stays, and How it runs needs its terms.
- A technology the code runs inside or extends (a host product), absent because no file of it is in scope.
- Generated code kept with no assumption saying why; a build or run definition (a pipeline, job control, a scheduler entry) outside the folders of the part it names: it belongs to that part, never to a part of its own, and a pipeline naming several parts stays covered as not code; files in scope in no part, by folder, with no reason.
- Something the code builds and someone runs, deploys or schedules with no part; a version a part uses with no use; a risk the code shows plainly (a secret written in clear text, a version long out of support) with no fact carrying it; a large folder kept whose ownership no file settles, with no assumption saying so.
