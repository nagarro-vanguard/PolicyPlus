# Capability rules

- **Script:** `S/explain-capability-rules.ts`. One lifecycle job per entity, `capability-rules/write-entity-lifecycle`, reads that entity's life wherever the whole system saves it; once every life is decided, the rules jobs, `capability-rules/write-business-rules`, read the blocks in scope; each job has its review `review/review-agent-findings` and its own brief.
- **Before the first `next`:** `S/explain-capability-rules.ts prepare --all` to study every capability, or `--capability "<name>"` naming each capability to study in that one call, each as its page names it (its record id where two share a name); a later call replaces the choice. It prints the jobs and the lines, and any jobs the Map refused, whose rules go unread: tell the person, and go on.
- **What the rules jobs read:** with `--all`, every mapped block, reached by an entry point or not (reach decides what a capability serves, not what the study reads); otherwise the blocks the chosen capabilities reach. Once every life is decided and before any rules job runs, the scope is cut again to include the block holding each accepted transition's `writtenAt` lines. The writer reads every line of its blocks and files one `Receipt` listing the ranges it read; a block with no rule is told by the absence of a rule, never by a record, and the reviewer hunts missed rules inside it.
- **At done:** tell the person what `show` reports; a refused job's capability reads incomplete. A rule in a block no entry point reaches is attributed to no capability. Go on to Publish.
- **After Publish:** to study a capability once Publish has run, run `S/publish-pages.ts prepare` first, then this stage, then Publish again.
